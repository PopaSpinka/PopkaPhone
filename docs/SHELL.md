# Оболочка НаомиФона

Код — `shell/` (CMake), собирается на телефоне в среде сборки ([DEVELOPMENT.md](DEVELOPMENT.md)):
`display/` — драйвер экрана для Qt, `app/` — оболочка-композитор и её QML, `ui/` — общий QML-модуль
`Naomi.Ui` (тема, подписи, переключатели) для оболочки и программ, `apps/` — программы.

```sh
tools/naomi build        # shell/ → телефон (~/naomi/src), сборка в среде → ~/naomi/build (≈ 6 с)
tools/naomi install      # один раз: службы в систему (автозапуск, безопасный режим, кнопка питания)
tools/naomi run [сек]    # перезапустить службу naomi-shell; с числом — показать журнал
tools/naomi stop
tools/naomi shot [имя]   # снимок экрана оболочки → reports/screens/ (SIGUSR2 → /tmp/naomi-shot.png)
tools/naomi touchtest    # плавность касаний: виртуальный палец + счётчики кадров
tools/naomi fonts        # шрифты интерфейса (Google Sans, см. «Шрифты») из downloads/fonts → телефон
```

## Служба

`tools/naomi install` (скрипт `device/install-shell.sh`, от root; `install uninstall` — убрать):

- `naomi-shell.service` — оболочка от `phablet`, автозапуск (`graphical.target`), перезапуск при падении
  через 1 с; код выхода 75 — просьба оболочки перезапустить её (новая ширина кадра, см. «Как запускается»), не
  падение. Окружение — в службе; добавочное — `~/naomi/shell.env` (его пишет `tools/naomi run` из
  `NAOMI_RUN_ENV`). Перед стартом от root `shell-prepare`: ждёт composer в Android-контейнере, даёт группам
  `video` и `android_input` писать яркость и команды контроллера касаний, читать прерывание датчика отпечатка
  (будит из AOD), группе `video` — аппаратный видеокодер (трансляция, [STREAM.md](STREAM.md)), выключает фильтр
  движения, подключает `schedtune` (`/dev/stune`, группа `desk` с `prefer_idle`; её ручки — `phablet`): подъём
  программ стола на большие ядра, пока стол смотрят ([WEB.md](WEB.md), «Большие ядра для стола»); ставит диску
  `/userdata` планировщик `noop` и ядру — запас свободной памяти ([ANDROID.md](ANDROID.md), «Память и диск»).
  `LimitMEMLOCK=infinity` — оболочка закрепляет в памяти свой код (`code_pin.*`: отображения файлов, по мере
  обращения; `NAOMI_PIN_CODE=0` — не закреплять): под нехватку памяти он не уходит на диск.
- Группа процессов службы отдана оболочке (`Delegate=yes`): программы стола живут в её подгруппе `desk`, и стол без
  зрителя замораживает их ядром ([DESKTOP.md](DESKTOP.md), «Выключатель»). `ExecStop` сначала оттаивает её —
  замороженная программа SIGTERM не прочтёт, и остановка (и перезапуск после падения) ждала бы её до SIGKILL.
- `naomi-safe.service` — **безопасный режим**: 4 падения за минуту → экран-заглушка (`safescreen.py`:
  тёмный, красная полоса вверху, янтарная внизу), SSH и ADB работают. `tools/naomi run` возвращает оболочку.
- `repowerd` (питание Ubuntu Touch, без Lomiri бесполезен) — `mask`; `logind` кнопку питания игнорирует
  (`/etc/systemd/logind.conf.d/90-naomi.conf`) — **иначе по умолчанию нажатие выключает телефон**.
- Файлы для root — `/usr/local/lib/naomi/`.
- Библиотеки Qt Wayland Compositor (в системе их нет) — `.deb` из кэша среды сборки, той же версии.
- Журнал systemd — в памяти (`/etc/systemd/journald.conf.d/90-naomi.conf`, до 64 МБ): на корне он дорос
  до 216 МБ и забил его до 100%.
- Остановка (SIGTERM): оболочка сначала мягко закрывает программы — им, чтобы сохраниться и выйти,
  нужен живой композитор, — и выходит, когда они закрылись (не дольше 2 с, потом SIGKILL). Замер:
  «Заметки» закрылись с кодом 0 за 37 мс, вся остановка — 0,13 с.

Проверено 10 ноября 2026: после перезагрузки служба стартует на 20,3 с, 90 Гц подтверждены на 21,9 с;
нарочно сломанная оболочка уходит в безопасный режим, `tools/naomi run` её возвращает.
Кнопка питания (виртуальной клавиатурой, `touchinject.py key 116`): экран гаснет, за 3 с ни одного
кадра; повторное нажатие — экран блокировки (её с 12 ноября 2026 нет: главный). Пользователь проверил живьём кнопку питания, разблокировку,
программы и жесты, шторку и яркость — «всё работает».

## Интерфейс

Палитра и типографика НаомиОС — общий модуль `Naomi.Ui` (`shell/ui/Naomi/Ui`, при сборке —
`~/naomi/build/qml`): `Theme.qml` (тёплый уголь, янтарь, подписи капсом с разрядкой — `Caps.qml`; шрифты —
см. «Шрифты»), `NSlider.qml`, `NToggle.qml` (долгое нажатие —
`held`), `NSlider.qml` (бегунок идёт за пальцем, потом снова за `value`), `NButton.qml`, `Bars.qml`, `Axis.qml`
(переход между двумя экранами — см. «Переходы»), `Spring.qml` (пружина SwiftUI для программ), `Spinner.qml`,
`MorphIcon.qml` со своим шейдером `shaders/morph.frag` (при сборке `qsb` переводит его в `morph.frag.qsb` для
OpenGL ES — версии 100 es, 120, 150, как у встроенного вершинного шейдера Qt, иначе «shader version mismatch»); в
`Theme` — `signalLevel` (столбики по 0…100) и `wifiLabel`.

**Крутилка ожидания — одна на всё: `Naomi.Ui/Spinner`** (выбор пользователя 12 ноября 2026: «везде, где нужна,
по умолчанию, и в будущем»). Это «Морфинг» из ПопкаТВ (НаомиОС, `popkatv/host/CardLoading.qml` — крутилка
поверх карточки, пока запускается фильм) без круглой тёмной подложки: белый контур 20 × 20 толщиной 2
перетекает круг → скруглённый квадрат (скругление 3, масштаб 0,85) → лист → круг, поворачиваясь на полный оборот,
1,8 с на круг (`size` меняет всё в той же доле, `color` — цвет). Крутится, только пока видна. Стоит: на заставке
запуска программы (по центру, вместо названия), «Наоми думает» в облачке ввода чата и ожидание подключения по QR,
сохранение, удаление и «потянуть — обновить» в блокноте. Проверено снимками 12 ноября 2026: заставка «Заметок» —
крутилка по центру без надписи; на кнопке «сохранить» (ответ сервера-копии задержан на 4 с) — три кадра подряд:
лист, скруглённый квадрат, лист под другим углом.

**Значок-трансформер `Naomi.Ui/MorphIcon`: плюс ⇄ крутилка одной фигурой** (просьба пользователя 12 ноября 2026:
не смена картинок, а превращение, плавно, без рывков, по кругу, без нагрузки на систему — и задел на другие формы).
Фигуру рисует шейдер полем расстояний до контура: плюс — два отрезка, кольцо, «Морфинг» — квадрат со своими
скруглениями; переход — перетекание одного поля в другое, каждый кадр — цельная гладкая фигура, край сглажен на
пиксель. Из четырёх вариантов, показанных на телефоне (лучи сворачиваются в кольцо, разворот в квадрат, кольцо
рисуется, втягивание), выбран «втягивание»: лучи стягиваются в точку, и точка без остановки раздувается в кольцо
(0,52 с, InOutCubic на весь переход — первая версия замирала в точке: у каждой половины был свой разгон, и
пользователь видел «конец и начало»); кольцо тут же крутится «Морфингом» — его круг начинается и кончается тем же
кольцом. Конец — крутилка докручивает свой круг до кольца и только тогда стягивается в плюс (0,46 с), не
обрываясь посреди оборота. Всё — цепочки `UniformAnimator` в потоке отрисовки (у программ он отдельный —
`threaded render loop`): передачи между частями не ждут поток интерфейса; перебили — продолжает с места
(остановленный аниматор возвращает положение в свойство — проверено журналом: уход на 1,156 оборота дал фазу
0,162). Новая форма — ещё одна функция расстояния в шейдере. Замеры на витрине (4 варианта ×2 размера, временная):
90 кадров/с, p95 11,3 мс; поток интерфейса занят 30 мс из каждых 46 — те же 90 кадров/с, один кадр 22 мс за 8 с;
пока значок стоит плюсом — кадров нет совсем. Стоит в облачке ввода чата вместо пары «плюс + крутилка».
Размеры в dp: экран 393 × 851.

**Жесты** (переходы — см. «Переходы»): снизу вверх — домой (программа-процесс остаётся жить); от левого края
вправо (зона 30 dp) — назад: сначала прячет клавиатуру оболочки, потом лист страницы, потом раздел программы,
потом закрывает программу (своя клавиатура программы — часть её окна: уходит вместе с ней; у программы с
открытым разделом — заголовок окна «‹ …» — «назад» ведёт она сама, см. «Окна программ»); от строки состояния вниз — шторка, смахнуть вверх по ней или касание ниже органов —
закрыть. Везде одно правило: смахнул — сработало (хватает 5 % пути или броска), вернул палец почти на место —
как было; без отскока.
Жесты работают и поверх окна программы:
они отбирают касание у окна, когда палец сдвинулся (окно получает отмену касания).

В 0.2 «назад» не срабатывал: к `onActiveChanged(false)` Qt уже обнулил `translation` у `DragHandler`, и
проверка «сдвинул больше 80 точек» не проходила. Теперь сдвиг запоминается по ходу жеста.

срабатывали ни разу, а начатые чуть выше (2303, 2287) — сразу; виртуальный палец повторил это точно: с 2339 —
0 из 7, с 2338 — всегда. Причина — округление в Qt: libinput даёт точку 1559,33 из 1560 строк кадра, в точках окна
(масштаб 1,83) — 850,55; окно — 851 точка (последняя строка 850), а окно для касания Qt ищет по точке, округлённой
до 851, — «ниже окна», и касание со всем смахом выбрасывается (журнал `qt.qpa.input.events`: касание есть, ни
один обработчик его не получил). Стол тут ни при чём — без него так же; от самого края смахивают, держа телефон
одной рукой. Исправлено калибровкой сенсора: правило udev `90-naomi-touch.rules` (`install-shell.sh`) сжимает высоту
на 0,05 % (`LIBINPUT_CALIBRATION_MATRIX`), последний ряд — 1558 (849,8 точки); внизу сдвиг меньше точки панели,
вверху — ноль. То же — у виртуального пальца `touchinject.py` (он повторяет сенсор). Проверено: с 2339 — 5 из 5.

**Экономия:** фон всех экранов и панелей — чистый чёрный (`Theme.canvas`, замер по снимку — (0, 0, 0)): у
AMOLED чёрная точка не светится, экран тратит меньше. Работы процессору и видеочипу это почти не убавляет —
кадр заливается всё равно; сколько экономит батарея — не замерено (телефон всё время на зарядке, ток —
заряда, а не расхода). Панели поверх (клавиатура, листы, громкость) — тоже чёрные, край — тонкой линией;
шторка — чёрный экран, под ней ничего не рисуется (главный и программа спрятаны, когда она открыта). Когда ничего не меняется, кадры не рисуются (HUD пишет «покой»); часы обновляются раз в
минуту; при выключенном экране драйвер кадры не выводит, опрос состояния и цифр кадров стоит.
**Открыть программу — один путь для всех** (`openApp` в `ShellView.qml`): готова — сразу переход; нет —
переход, когда будет готова. «Наоми» и «Заметки» — процессы: запускаются один раз и живут, готовы, когда их окно
нарисовано. «Настройки» — страница оболочки, но живут так же: создаются один раз, в фоне после запуска оболочки,
после закрытия не выгружаются, а прячутся, и открываются там же, где были (раздел, прокрутка) — как блокнот с
открытой заметкой. Спрятанные ничего не опрашивают; опрос «о телефоне» и «нагрузки» — только когда переход
закончился. Заставка программы, которая только запускается (крутилка), и страница экрана проекта создаются в фоне
(`Loader.asynchronous`) — создание посреди анимации стоило кадра; самое первое открытие экрана проекта может
стоить одного кадра (Qt компилирует его QML), дальше — из кэша. Замер — в «Переходах».
Датчик света работает, только пока горит экран и включена автояркость.

## Автояркость

Плитка «автояркость» в шторке и «Настройках» (по умолчанию включена; на плитке — освещённость в люксах).
Освещённость — датчик света через `naomid` (`naomiPhone.sensors.light`: оболочка просит его, пока экран
горит); яркость считает `naomiPower` (`shell/app/power.*`):

- кривая по восприятию (0…1) от логарифма освещённости: 0 лк → 0,10, 10 → 0,35, 100 → 0,58, 1000 → 0,82,
  10 000 → 1; на подсветку — квадрат этого (как и у ползунка);
- ползунок при автояркости не выключает её, а сдвигает кривую, как в Android: яркость = кривая^(3^−сдвиг),
  сдвиг −1…1 — края 0 и 1 на месте, середина ярче или темнее. В первый раз сдвиг берётся из ручной
  яркости — экран не меняется от включения автояркости;
- стало светлее на 10 % — ярче через 1,5 с, темнее на 20 % — темнее через 4 с: тень руки не мигает
  экраном; вернулось в полосу — ничего. Смена плавная: светлее 0,6 шкалы в секунду, темнее 0,25;
- экран включили — первое значение датчика принимается сразу (за ≈ 0,3 с); экран погашен — всё стоит.

Выбор — `~/.config/naomi/shell.conf`: `display/auto`, `display/autoAdjust`, ручная — `display/brightness`.

Проверено пользователем 10 ноября 2026 (журнал `naomi.power`, ещё в Android-интерфейсе — логика та же):
включили экран — 25 лк, яркость сразу 0,76; стало 35 лк — ярче через 1,5 с; ладонь на датчике — 13 лк,
темнее через 4 с (датчик под экраном: закрытый ладонью он видит не ноль); ползунок сдвинул кривую темнее
(сдвиг −0,35), дальше яркость шла по новой кривой. После возврата интерфейса: 14 лк → 0,65 с тем же сдвигом,
плитка показывает люксы.

QML читается с диска рядом с программой (`~/naomi/build/app/qml`, или `NAOMI_QML`): правка интерфейса
не требует пересборки C++ (сейчас `tools/naomi build` всё равно копирует его заново).

## AOD

«Экран всегда включён»: гашение уводит не в темноту, а в AOD — **главный экран, притушенный на месте**
(`AodScreen.qml`; решение пользователя, 12 ноября 2026: экрана блокировки нет, «главный просто потухает до той
яркости, что была у блокировки, без деформации»). Копии нет: поверх всего — чёрный до 0,4, под ним живой главный,
обои проекта под ним — ещё на 35 % темнее (часы и список читаются), яркость панели — уровня AOD. Плитки в шторке и «Настройках»: «aod» — по кругу «выкл» (по умолчанию) → «вкл» (со второй ступенью,
ниже) → «без экономии» (без неё); рядом «aod через» — через сколько секунд без касаний уходить в AOD:
10 с / 1 / 3 / 5 / 10 мин / никогда (без AOD та же плитка называется «гасить экран» и гасит совсем). Это и
«автоблокировка»: экран гаснет (блокировки нет — проснётся главный). Шаги — просьба пользователя (12 ноября 2026; было 10 / 15 / 30 с / 1 /
5 мин); значение не из шагов (15, 30 с — со старых времён или из студии) касание ведёт на следующий шаг выше.
Выбор — `~/.config/naomi/shell.conf`: `display/aod`, `display/aodDeep`, `display/timeout`. С проектом студии AOD —
его главный, притушенный, с обоями (System → Wallpaper → Always On), а если в проекте есть свой экран Always On — он.

- **Вход:** кнопка питания при включённом экране или «aod через» без касаний. Оболочка уходит на главный
  (программа живёт дальше, как после «домой»).
- **Выход** — на главный: касание экрана (само касание интерфейсу не идёт до отпускания пальца —
  под ним мог быть орган), касание датчика отпечатка, кнопка питания. Кнопки громкости в AOD ничего не делают (пока смотрят рабочий стол — меняют громкость его звука).
- **Панель остаётся включённой** в обычном режиме, AOD — свой экран при низкой яркости: 0,3 по восприятию
  (подсветка 96 из 1023, ≈ 47 нит), а если экран и так был темнее — та же. Панель s6e3hc2 — командная
  (`qcom,mdss-dsi-panel-type = dsi_cmd_mode`): картинку держит в своей памяти, между кадрами ей ничего не шлётся;
  опустить частоту самой панели до 1 Гц, как у LTPO-экранов iPhone, нельзя — у неё 60 и 90 Гц и малое питание

  - свой экран Always On проекта — через чёрный в обе стороны.

**Было — и что нашли записью по кадрам** (пользователь: «криво работает», потом — «мигает»; тогда AOD был часами

  прошедшее время — выход доходил до конца за 3 мс. Теперь ход считает `naomiPower` по кадрам окна

- **Контур двоился** (пользователь: «сдвигается, как-то странно деформируется»): часы AOD были тоньше и
  смещались против выгорания отдельно от часов блокировки — в середине перехода видны были две копии,

  на тех же снимках одни часы.

**Не измерено:** расход батареи в AOD (телефон был на зарядке) — панель в обычном режиме тратит больше, чем
в малом питании; сколько — замер без кабеля ([POWER.md](POWER.md)).
**Нет защиты в кармане:** касание через ткань разбудит — датчик приближения пока не используется.

## Окна программ (Wayland)

Оболочка — Wayland-композитор (Qt Wayland Compositor, QML). Программа — отдельный процесс, клиент на
сокете `wayland-naomi`: упадёт или зависнет — оболочка живёт. Её окно оболочка показывает в своём
единственном окне на экране (`ShellSurfaceItem`), касания и ввод текста передаёт ей.

- **Запуск** — `naomiApps.launch("имя")` → `~/naomi/build/apps/имя/naomi-имя`. Окружение:
  `QT_QPA_PLATFORM=wayland`, `EGL_PLATFORM=wayland` (GPU через libhybris, как у оболочки),
  `QT_WAYLAND_DISABLE_WINDOWDECORATION=1`; переменные оболочки (`QT_IM_MODULE`, `QT_PLUGIN_PATH`, …)
  убраны. Вывод программы — в журнал оболочки. Окно узнаётся по pid клиента Wayland.
- **Буфер окна обменивается без копий:** программа рисует в буфер Android (gralloc), оболочка берёт его
  как текстуру (EGL `EGL_WL_bind_wayland_display` в libhybris + серверный плагин Qt `wayland-egl`).
- **Дробная плотность 2,75 без размытия:** программа рисует в пикселях панели (`QT_SCALE_FACTOR=2.75`,
  вывод Wayland с масштабом 1), оболочка просит у неё размер в целых пикселях (xdg fullscreen):
  1080 × 2202 под полосой выреза камеры (клавиатура у программ своя, в окне: под неё окно не сжимается; ниже
  — только под клавиатуру оболочки, у программ без своей), — и показывает окно размером буфера
  ÷ 2,75 с верхним краем на целом пикселе (138). Чат — во весь экран, 1080 × 2340 от верхнего края
  (`underCutout` в `ShellView.qml`): что попадёт под вырез, решает сам — у него туда уходит лента.
  Текстура ложится на экран 1:1. Окно оболочки в точках округлено (393 × 851 = 1080,75 × 2340,25 пикселя),
  поэтому размеры считаются от пикселей, а не от точек.
- **Место окна задаёт оболочка:** xdg-интеграция Qt ставит fullscreen-окно в угол вывода (0, 0) —
  ей дана пустышка `moveItem`.
- **«Назад» у программы со своими разделами.** Программа, у которой открыт свой раздел (заметка в блокноте),
  ставит заголовок окна с «‹» в начале (`xdg_toplevel.set_title`, в QML — `Window.title`). Пока так, зону
  «назад» у левого края оболочка выключает: касание достаётся окну, и раздел закрывает сама программа — пальцем
  ведёт переход, как разделы «Настроек». Раздел закрыт — заголовок без «‹», «назад» снова закрывает программу.
- **Касания — в пикселях программы.** `ShellSurfaceItem` размером с буфер (в пикселях) и уменьшен в 2,75 раза:
  координаты внутри него и есть координаты окна программы. Qt Wayland отдаёт программе касания как есть, не
  пересчитывая под размер окна (мышь — пересчитывая); пока окно было размером в точках, палец попадал в 2,75
  раза ближе к углу — курсор в «Заметках» вставал в первую строку.
- **Активна только открытая программа.** Программа Qt считает своё окно активным, пока у него фокус
  клавиатуры Wayland (`wl_keyboard`; флаг xdg `activated` она при наличии клавиатуры не смотрит). Дома и
  при погасшем экране оболочка снимает этот фокус (`naomiApps.releaseFocus`): поле теряет фокус,
  курсор не мигает, программа ничего не рисует. Открыли снова — фокус возвращается.
  Замер, «Заметки» с полем в фокусе: экран включён — оболочка 2,1%, программа 1,1% одного ядра (курсор
  мигает, 2 кадра в секунду); дома и при погасшем экране — **0 тиков процессора за 10 с** у обоих.

- **Окна Android** (Waydroid, [ANDROID.md](ANDROID.md)) узнаются не по pid, а по группе процессов клиента
  (`lxc.payload.waydroid`, `naomiAndroid.isAndroid`) и уходят столу. Для них у композитора есть `wp_viewporter`
  (`QWaylandViewporter` в `main.cpp`: Waydroid кладёт слои приложения подповерхностями с обрезкой через него).
- **Программы стола** (браузер, [WEB.md](WEB.md)) рисуют не для экрана телефона, а для рабочего стола
  ([DESKTOP.md](DESKTOP.md)): `naomiApps.launch(имя, 1.5)` — масштаб стола, окно такой программы `Main.qml` отдаёт
  столу (`naomiApps.deskWindow`). Фокус клавиатуры у окна стола оболочка, уходя домой или гася экран, не снимает
  (`releaseFocus`): на столе в это время печатают.

### Кадры программ

Программа рисует следующий кадр, когда оболочка ответит на прошлый «рисуй дальше» (frame callback Wayland).
Оболочка отвечает после своей отрисовки — из потока интерфейса.

**Было (нашёл пользователь: «лагает, когда веду палец по чату»):** пока палец на экране, программы рисовали
**45 кадров в секунду** при 90 у оболочки. Замер — журнал протокола (`WAYLAND_DEBUG=client`) и время кадров
(`QSG_RENDER_TIMING=1`): от отправки кадра программой до ответа оболочки — 21,4 мс под пальцем и 10,6 мс без
него. Поток интерфейса оболочки ~10 мс из каждых 11 стоял в синхронизации (`blockedForSync`, «Касания»). Кадр
программы и ответ ей проходили только в короткое окно после синхронизации, то есть через кадр. Отсюда новое
расписание кадров оболочки («Касания»).

**Касание — раньше ответа.** Wayland копит события до простоя потока интерфейса. Касание, которое Qt Quick
отдаёт окну программы в начале кадра оболочки, порой уходило одним пакетом с ответом «рисуй дальше». Программа
начинала кадр, не прочтя касания: кадр без сдвига, следом двойной шаг. Теперь оболочка сбрасывает события
программам в начале синхронизации (`wl_display_flush_clients` в `beforeSynchronizing`, `main.cpp`; поток
интерфейса в это время стоит).

**Замер 11 ноября 2026** (чат «Наоми», виртуальный палец ведёт ленту вниз через клавиатуру 1,2 с):

| | кадр программы под пальцем, медиана | кадров ≤ 13 мс |
|---|---|---|
| было | 22 мс (45 к/с) | 0 из 55 |
| стало | 11,2 мс (90 к/с) | 118 из 126 |

Кадры без сдвига (палец двигался, а в кадре программы — то же место) — по временной записи положения пальца
в каждом кадре программы (в проект не вошла): 14 из 109 до сброса касаний в начале синхронизации, 1 из 107
после — в первом кадре жеста.

Оболочка в переходах (открыть программу, «домой», снова открыть, блокировка): поток интерфейса стоял в
синхронизации ≥ 5 мс в 136 кадрах из 235, стало 0 из 225 (максимум 4 мс). Пропусков кадров — 2 вместо 8, и
те на краях анимаций (кадр после покоя).

## Клавиатура

Своя (`Naomi.Ui/Keyboard.qml`), одна и та же везде: у оболочки — поверх, для её полей («Настройки»), у каждой
программы — в её окне ([KEYBOARD.md](KEYBOARD.md), «В окне программы»). Модуль ввода Qt «naomi»
(`shell/input/keyboard_context.*`; `QT_IM_MODULE=naomi` оболочка ставит себе и программам) узнаёт от Qt, когда
поле просит клавиатуру, и через него клавиатура печатает в то, что в фокусе: текст — `QInputMethodEvent`,
«стереть» и «ввод» — клавишами. Программам без своей клавиатуры оболочка по-прежнему может печатать через
протоколы text-input (`zwp_text_input_v2`, `v3`, `qt_text_input_method_v1`).

- Вид и места клавиш — 1:1 с клавиатурой iOS по снимку пользователя, цвета свои; пробел исправляет
  опечатки по точкам касаний ([KEYBOARD.md](KEYBOARD.md)).
- Раскладки: русская ЙЦУКЕН (11 клавиш в ряд), английская QWERTY; две страницы цифр и знаков («123»:
  цифры, `-/:;()₽&@"` (в английской — `$`), `. , ? ! '`; «#+=»: скобки, `#%^*+=`, `_\|~<>€£¥•`). Нижний ряд
  — «123», «Пробел», «Ввод». Пробел на странице знаков возвращает к буквам; два пробела подряд после
  слова — «. » (как в iOS).
- Мультитач одной областью: можно печатать двумя пальцами внахлёст. Буква вводится при отпускании —
  та, что под пальцем в этот момент (можно доскользить до нужной); над пальцем — увеличенная буква.
- Долгое нажатие: е → ё, ь → ъ, верхний ряд — цифры (подсказка в углу увеличенной буквы); «стереть»
  повторяется (через 0,42 с, потом каждые 60 мс).
- Заглавная — сама в начале текста, после «. ! ? …» и с новой строки; ⇧ — одна заглавная, дважды — капс.
- Выезжает за 320 мс, уходит за 280 (кривая OutCubic; было 240 / 200 — пользователь: «чуть медленнее»),
  поле прокручивается к курсору. В «Заметках» — с первого касания поля (Qt сам открывает клавиатуру только по касанию уже выбранного поля)
  и снова, когда вернулись в программу с выбранным полем.
- Под клавишами, как в iOS: глобус слева — русская ↔ английская, «спрятать» справа (на месте микрофона);
  ниже — полоса жеста «домой». Спрятать можно и жестом «назад».
- Значки ⇧ ⌫, глобуса и «спрятать» — Material Symbols (как SF Symbols в iOS).
- Поле подсказывает, как вводить (`inputMethodHints`, клавиатура читает их через `naomiKeyboard.hints()`):
  пароль, адрес, «без заглавных» — заглавная сама не ставится; «только латиница» — клавиатура открывается

## Проект студии

Студия NaomiPhone (редактор экранов на Mac; в открытую версию не вошла) собирает экраны телефона, кнопка **Load** кладёт проект
на телефон — `~/.config/naomi/project.json` (с ним `studio`: id проекта в студии, его правка, когда загружен). Оболочка
следит за файлом (`naomiProject`, `project_file.*`: папка и файл в QFileSystemWatcher — Load пишет рядом и
переименовывает) и меняет экраны сразу, без перезапуска (замер 12 ноября 2026: Load одного проекта — 0,2 с от кнопки до
«Done»). **Live** студии пишет тот же файл на каждую правку (одно открытое SSH-соединение, 3–5 мс по кабелю);
оболочка читает его не позже чем через 16 мс после перемены и не ждёт тишины — при перетаскивании слой едет за
пальцем в студии. Файла нет или он не читается — свои экраны, как раньше.

- Экраны рисует общий модуль **`Naomi.Screens`** (`shell/ui/Naomi/Screens`): `ScreenView` — экран проекта, слои — по
  файлу на вид (`layers/ClockLayer.qml`, `DateLayer`, `ChargeLayer`, `BatteryLayer`, `WeatherLayer`, `TextLayer`,
  `PanelLayer` — Background: чёрный верх и панель со сглаженными углами,
  `AppsLayer`, `AppLayer`), обои — `Wallpaper.qml`. `WeatherLayer` сам спрашивает погоду у Open-Meteo (api.open-meteo.com, раз в 30 минут,
  координаты города из проекта) — телефону нужен интернет. Тот же
  QML исполняет движок студии в браузере — что на карте студии, то и на телефоне.
- Первый экран проекта — **главный** (`HomeScreen.qml`: вместо своего списка — его слои; строка программы открывает
  программу телефона с тем же именем — `apps[row].id`: `chat`, `notes`, `settings`); с него телефон начинается.
  Блокировки нет (решение пользователя, 12 ноября 2026); у проектов, сделанных, пока она была, первый экран был
  блокировкой, а главный — их `main`: оболочка берёт главный по `main`, студия при открытии ставит его первым.
- **Остальные экраны** открывают ссылки слоёв (`tap.to`): экран проекта поверх главного — как программа
  `"screen:<id>"` (`ProjectPage.qml`: тот же переход открытия, «домой» снизу закрывает). Внутри — стопка, как Try
  студии: ссылка — следующий экран (Axis без направления, 300 мс), «назад» от левого края — предыдущий (вбок, 260 мс,

  программа. Касание ловят только слои со ссылкой.
- Главный экран ловит касания, только когда он сверху (`enabled`): обработчики касаний слоёв не забирают касание
  целиком, и касание по слою над ним доходило до строки программы под ним (запускался чат).
- **Шторка** — своя (`QuickSettings.qml`); с проектом тянется, только если на его главном есть слой «shade».
- **Обои** проекта (`functions.wallpaper` — System → Wallpaper студии: картинка `file`, `scale` — 1 закрывает экран,

## Программы

Программ-процессов телефона в открытой версии нет: чат «Наоми» и блокнот «Заметки» работали только с сервером
НаомиОС автора и не вошли. Как устроена такая программа — ниже.

Программа — обычная Qt Quick: просит OpenGL ES до создания `QGuiApplication` (Qt в Ubuntu собран под
настольный GL), подключает `Naomi.Ui` из `<сборка>/qml`, по SIGTERM выходит (блокнот при этом ничего не
сохраняет сам: карточку сохраняет только галочка, как в iOS).

## Как запускается

Окружение (служба `naomi-shell`): `QT_QPA_PLATFORM=eglfs`, `QT_QPA_EGLFS_INTEGRATION=eglfs_naomi`,
`QT_PLUGIN_PATH=~/naomi/build/plugins`, `EGL_PLATFORM=hwcomposer`, `XDG_RUNTIME_DIR=/run/user/32011`;
`QT_IM_MODULE=naomi` оболочка ставит себе сама (и программам — app_launcher).
От пользователя `phablet` (группы `android_input`, `android_graphics`, `video`, `audio`, `input`);
доступа к composer HAL ему хватает. Ввод — libinput из eglfs (кнопки и сенсорный экран).
Необязательно: `NAOMI_REFRESH` (60/90, по умолчанию 90), `NAOMI_DENSITY` (плотность на полной ширине, по умолчанию
2,75), `NAOMI_RENDER` — ширина кадра (720: кадр 720 × 1560, его растягивает дисплей, плотность 1,833 —
[DISPLAY.md](DISPLAY.md), «Кадр меньше панели»); без неё — выбор плитки «разрешение» (`display/render` в
`shell.conf`, по умолчанию 1080). Программам оболочка передаёт ту же плотность (`QT_SCALE_FACTOR`).

## Что важно знать о драйвере

- **Qt 6 в Ubuntu собран под настольный OpenGL**, а Adreno через Android EGL — только OpenGL ES. Драйвер
  просит ES 3.0 в `surfaceFormatFor`; без этого — «Cannot find EGLConfig». Получается ES 3.2, Adreno 620.
- **Плагин собирается с `QT_EGL_NO_X11`**, иначе `EGLNativeDisplayType` = `_XDisplay*` и плагин не
  загрузится (`undefined symbol …createDisplayEP9_XDisplay`).
- **`android_dlopen/android_dlsym`** объявлены в `hybris/common/binding.h` без `extern "C"` — драйвер
  объявляет их сам.
- **Частота включается, когда кадры уже идут** и подтверждается замером интервалов, а не ответом
  composer — подробности в [DISPLAY.md](DISPLAY.md), «Смена частоты».
- Плотность 2,75 (как xxhdpi Android): логический экран 393 × 851, 1 логический пиксель = 1 dp.
- Все вызовы composer — в потоке отрисовки Qt Quick; смена частоты из интерфейса — заявка.

## Касания

Сенсор Pixel 5 (`sec_touchscreen`, `/dev/input/event2`, 1080 × 2340, 10 контактов) шлёт **180 кадров
касания в секунду** ровно через 5,56 мс, без потерь и скачков (`device/touchrec.py`: сырые события и время
их доставки). Qt читает его через libinput (eglfs).

**Было:** кольцо под пальцем дёргалось. Разбор (`NAOMI_TRACE`, виртуальный палец `device/touchinject.py`):
в окно касания приходили пачками — кадр с 0 событий, кадр с 4, — и обработчик в QML обновлялся 45 раз в
секунду при 90 Гц экрана. Временная шкала потоков показала причину: на eglfs `QWindow::requestUpdate`
отдаётся таймером через 5 мс (`QT_QPA_UPDATE_IDLE_TIME`). Qt Quick начинал следующий кадр посреди вывода
текущего, поток интерфейса ждал синхронизации до vsync (present у composer Qualcomm ждёт vsync ≈ 10 мс) и
через кадр не успевал прочесть ввод. Не помогли: однопоточный цикл Qt, свой цикл событий вместо glib,
чтение касаний в отдельном потоке (evdev), третий буфер окна, отдельный поток вывода.

**Стало:** кадр Qt Quick начинается, когда кончился обмен буферов прошлого (как vsync у Android и Wayland),
а если в пути ничего — сразу (`shell/display/naomi_hwc.cpp`: своё окно eglfs с `requestUpdate`, конец обмена —
`presentBuffer`). В пути не больше одного кадра: поток интерфейса в синхронизации не ждёт, а каждый кадр
получает свои касания. `tools/naomi touchtest` — 259 кадров жеста: 257 по 2 касания, 2 по одному, без касаний 0.

Сначала было `QT_QPA_UPDATE_IDLE_TIME=0` — кадр сразу по просьбе. Касания так тоже шли каждый кадр, но поток
интерфейса просил новый кадр, пока прошлый ещё выводился, и стоял в синхронизации до vsync ≈ 10 мс из 11.
Стоя, он не читал Wayland — программы под пальцем рисовали 45 кадров в секунду («Окна программ», «Кадры
программ»).

Проверка: `tools/naomi touchtest` (виртуальный палец ведёт круг 3 с, 180 Гц). В первом кадре жеста
бывает один пропуск кадра — это подключение виртуального устройства (настоящий сенсор подключён всегда).

**Фильтр движения контроллера.** Драйвер `sec_touch` (ядро redbull, `update_motion_filter`) через 0,5 с
касания одним пальцем включает в контроллере фильтр движения: точка приходит, только когда палец
сдвинулся заметно. Сенсор тогда молчит по 11–28 мс («застрял — догнал»). Выключение:
`echo set_continuous_report_enable,1 > /sys/class/sec/tsp/cmd` (root) — контроллер шлёт точки непрерывно,
драйвер фильтр больше не трогает. Замер настоящим пальцем: было 19 пауз длиннее 8 мс (до 27,8 мс),
стало 0 из 797, самая длинная 6,1 мс. Пользователь: «стало лучше». **Пока действует до перезагрузки** —
закрепить в службе оболочки при старте и после включения экрана.

Пользователь замечал «застревание» кольца над живой полосой (линия, ромбы). Замеры этого не подтвердили:
сенсор над полосой ровный, а повтор его настоящего пути виртуальным пальцем (`touchinject.py replay`) даёт
обновление кольца каждый кадр. Возможно, на фоне движения заметнее задержка кольца (≈ 3 кадра) — отложено
по решению пользователя; помогут замер задержки «касание → кадр» и предсказание движения пальца.

## Отладка

- `NAOMI_TRACE=1` — раз в секунду `naomi-trace`: продвижения анимаций, синхронизации, кадры, касания,
  самая длинная пауза между касаниями, как касания разложились по кадрам, и кольцо — сколько кадров
  касания прошло без обновления обработчика в QML, его самая длинная пауза и шаг (`shell/app/dev_trace.*`,
  из QML — `naomiTrace.handlerPoint`).
- Виртуальный палец `device/touchinject.py`: `circle`, `swipe`, `zigzag` (змейка по полосе),
  `tap X Y [X Y …] [--gap с]` — касания по очереди одним устройством (так набирается текст на клавиатуре),
  `replay --file` — повтор пути настоящего пальца из `touchrec.py --frames` с исходными таймингами,
  `key КОД` — клавиша (116 — питание). Каждый запуск подключает новое устройство: первое касание бывает
  потеряно, а подключение посреди анимации стоит кадра — между действиями нужна пауза.
- Пропуском кадра считается пауза от 1,5 до 6 периодов; длиннее — покой, не пропуск.
- `NAOMI_TRACE=timeline` — плюс один раз временная шкала потоков (≈ 0,25 с): A — анимации, S/s —
  синхронизация, R — отрисовано, W — кадр отдан, t — касание.
- `NAOMI_FRAMESTATS=1` (включён в службе) — `naomi-frames`: кадры по present-fence.
  `NAOMI_FRAMESTATS=drops` — ещё и `naomi-drop` на каждый пропуск: до 9 интервалов перед ним, сам он
  `[в скобках]`, кадры после; `покой→` / `→покой` — пауза дольше 6 периодов. Видно, рывок это посреди
  анимации или край (первый кадр анимации после касания, последний кадр программы после анимации).
- `WAYLAND_DEBUG=client` в окружении оболочки — программы пишут свой протокол Wayland в журнал.
- `NAOMI_RUN_ENV="K=V …" tools/naomi run` — запустить с добавочным окружением.

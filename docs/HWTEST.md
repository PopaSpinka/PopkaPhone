Живые тесты: устройство включается по-настоящему, результат проверяется (`device/hwtest.py`,
запуск — `tools/naomi test [тест …]`, отчёты — `reports/hwtest-*.json`, не в git). Нагрев —
`tools/naomi stress` (`device/stress.py`). Одни и те же тесты гоняем на штатном Ubuntu Touch и потом на
НаомиФоне — так видно, что мы ничего не потеряли.

### Находки

- **Одновременные запись и воспроизведение вешают PulseAudio.** Запись при играющем звуке пустая,
  в журнале сыплются `q overrun, queuing locally`, служба перестаёт принимать подключения и не
  останавливается по `systemctl --user restart` (убивается через 90 с), после чего не поднимается —
  помогла только перезагрузка. Это важно для звонков по VoIP и будущего голоса Наоми. Пока тесты звука идут
  строго по очереди. 16 ноября 2026 — то же от записи с монитора выхода: пропал источник — PulseAudio перенёс запись
  на источник по умолчанию (микрофон); перезапуск `vendor.audio-hal` и `vendor.adsprpcd_audiopd` в контейнере тоже не
  помог. Своя запись теперь — с `PA_STREAM_DONT_MOVE` ([PI.md](PI.md), «Звук на мониторе»); после перезагрузки
  громкость динамика — 100 % (PulseAudio её не помнит — теперь помнит naomid, [NAOMID.md](NAOMID.md)). И без всякой
  записи `systemctl --user restart pulseaudio` вешает звук так же (16 ноября 2026, здоровый PulseAudio: выход завис в
  драйвере, новый не поднялся) — менять настройки PulseAudio только перезагрузкой телефона.
- **Громкость динамика драйвер теряет при пробуждении.** Присланную, пока поток спит, при запуске не применяет —
  после 5 с тишины динамик играл на 100 % при любой громкости в шторке; громкость динамика теперь — в PulseAudio
  (`hw_volume=false`, [NAOMID.md](NAOMID.md), «Громкость динамика»).
- **ADB по кабелю ненадёжен.** Режим USB выбирает служба `usb-moded` (из Sailfish). После перезагрузки
  она включила `developer_mode` — это сеть RNDIS без ADB, а RNDIS macOS без драйверов не понимает;
  в настройках при этом записан `mtp_adb`. Вернуть ADB:
  `gdbus call --system --dest com.meego.usb_moded --object-path /com/meego/usb_moded --method com.meego.usb_moded.set_mode mtp_adb`.
  Кроме того, `usb-moded` перезапускает `adbd`, когда заново применяет режим, — SSH через `adb forward`
  при этом обрывается (так оборвался первый прогон камеры). Пока `tools/naomi` идёт по Wi-Fi, если ADB
  нет, а `NAOMI_VIA=wifi` — и при живом ADB. Для режима разработчика НаомиФона нужен свой режим USB,
  который не зависит от блокировки и не переключается сам: ADB + сеть ECM/NCM (её macOS понимает без
  драйверов). **Сделано:** служба `naomi-usb` — ADB и сеть NCM всегда
  ([DEVELOPMENT.md](DEVELOPMENT.md), «Кабель»).
- **Загрузка:** первая — 5 мин 55 с (из них 5 мин 36 с — `snapd.seeded`), обычная — 21 с
  (3,4 с ядро + 18 с система).
- **Модем:** для проверки предпочтение сети переключено с `nr` (5G) на `lte`.

# Платы ESP32

Просьба пользователя 21 ноября 2026: чтобы его редактор экранов для плат ESP32 (PopkaStudio) работал на столе
телефона — видел плату по USB и прошивал её. Телефон стоит на кабеле к приставке Pi, и плату вставляют в Pi.

Сделано: **плата в Pi видна на телефоне как своя** — `/dev/ttyACM0` с её же производителем, моделью и серийным
номером (MAC платы), со сбросом и режимом загрузчика, как если бы её вставили в телефон; прошивка платы с телефона
проверена. Окно редактора на столе в открытую версию не вошло — здесь только проброс плат и драйверы.

## Как устроено

```
плата ESP32 ──USB── Pi: usbip-host (ядро Pi) ◀── naomi-usbshare (pi/usbshare) слушает 10.77.0.53:3240
                                   │ кабель телефон ↔ Pi, сеть CDC-NCM
телефон: naomi-usbshare (device/) ─┘ берёт плату → vhci-hcd → USB-шина 1 телефона → cdc-acm → /dev/ttyACM0
```

- **USB/IP** — проброс USB по сети, весь в ядрах (Pi: `usbip-host`; телефон: `vhci-hcd`). Обмен в начале — свой
  код на Python, но формат — стандартный (версия 0x0111: `OP_REQ_DEVLIST`, `OP_REQ_IMPORT`), сторонние `usbip`
  не нужны. Дальше ядро Pi и ядро телефона говорят сами по переданному им сокету.
- **Отдаются только платы:** Espressif `303a:*` (свой USB чипа: USB-Serial-JTAG `303a:1001`) и мост WCH CH343
  `1a86:55d3` (второй порт плат P4 и LCD-4B) — те, что знает PopkaStudio. Мышь, клавиатура Pi и сам телефон — нет.
- **Только по кабелю:** приставка слушает свой постоянный адрес на кабеле `10.77.0.53` (`IP_FREEBIND` — адрес
  появляется вместе с телефоном). У USB/IP нет пароля — поэтому ни домашней сети, ни Wi-Fi. Телефон на Wi-Fi без
  кабеля — плата остаётся на Pi.
- **Кабель выдернули:** у переданного ядрам сокета — TCP keepalive (5 с тишины, 3 пробы по 2 с): мёртвое соединение
  закрывается само, плата снова свободна. Телефон спрашивает приставку раз в 2 с и забирает свободные платы.
- **Служба остановилась на Pi** — платы возвращаются Pi (её `cdc_acm`, `/dev/ttyACM0` там).

## Драйверы: чего нет в ядре телефона

В ядре порта (`4.19.269-g5278bca141e1`, Android 4.19 от dadrickpistachio) выключены `CONFIG_USB_ACM` (порт платы
`/dev/ttyACM…` — все платы PopkaStudio через него), `CONFIG_USB_SERIAL` и `CONFIG_USBIP_*`. Модули ядро принимает
(`MODULES=y`, подписи нет, LTO выкл.) — три модуля собраны под него: `cdc-acm.ko`, `usbip-core.ko`, `vhci-hcd.ko`.

`device/kmod.py` (на телефоне, ≈ 80 с, нагрева нет — 35,9 → 36,6 °C):

1. **Исходник** — архив коммита порта `5278bca141e1` с GitHub (`dadrickpistachio/android_kernel_google_redbull`,
   193 МБ, SHA-256 `49b3fa94…f72d` записан в скрипте); **конфиг** — `/proc/config.gz` работающего ядра, включены три
   модуля. Разница с ядром допускается только в версии компилятора (Ubuntu clang 14.0.6 в среде сборки, у ядра —
   Android clang 14.0.7) и `RELR` (выключен, как у ядра); иначе скрипт останавливается.
2. `make modules_prepare` в среде сборки (`devroot`, clang-14, lld-14, llvm-14, bc, libssl-dev — 59 МБ, поставлены
   21 ноября 2026).
3. **Версии функций ядра** (`MODVERSIONS`): ядро прячет свою таблицу (`kptr_restrict=2` — настройка безопасности,
   её не трогаем). Берём из модулей самого порта (`/lib/modules/4.19.269-g5278bca141e1`, 328 модулей, 3806 версий,
   без расхождений). Модули из `/vendor/lib/modules` не годятся — они от заводской сборки Google
   (`g8728c337137c`), их версии не те. Нужные функции, которых нет ни в одном модуле порта (61 — ядро USB, tty,
   сокеты), — из сборки 13 файлов ядра, где они объявлены; остальные версии из этих же файлов сверяются с модулями
   порта: **83 из 83 совпали** (в 8 файлах, где было с чем сверить) — исходник и конфиг те же.
4. Модули собираются **внешними** (`M=`): только тогда modpost читает таблицу версий (при сборке «внутри дерева» он
   ждёт `vmlinux`). Проверка: у каждой функции ядра в модуле есть версия, `vermagic` — ровно версия ядра.

Сборка повторяется байт в байт (проверено: с нуля — те же SHA-256):

```
35b75cfa9965c6d5690c58587349798294b62e704d2975be7fe5507f14142ebb  cdc-acm.ko
7ca528378789abdad049ea06afc57fdb725fbe4402de5b972bfa37d359536d44  usbip-core.ko
3e2218190cddace05bfe1bfdcd2f8ca197f7aa289ea5b33a05600261f2b0d3de  vhci-hcd.ko
```

Лежат в `~/naomi/kmod/4.19.269-g5278bca141e1/` (+ `SHA256SUMS`); грузит их служба телефона (`insmod`). Ядро
загрузило все три без единой жалобы на версии; пометка ядра — «O» (модуль не из сборки ядра), других нет.
Исходники остаются в `~/kernel` (1,4 ГБ) — для следующей сборки без скачивания.

## Команды

```sh
tools/boards build        # драйверы на телефоне (device/kmod.py)
tools/boards install      # службы naomi-usbshare на Pi и на телефоне
tools/boards status       # что на телефоне, что на Pi
tools/boards uninstall    # убрать обе; платы — снова Pi
```

Службы: на Pi — `/usr/local/sbin/naomi-usbshare` + `naomi-usbshare.service` (root); на телефоне — то же, ставится
с переводом корня на запись и обратно. `naomi-usbshare status` на телефоне — драйверы, взятые платы, свободные на Pi.

## Проверено 21 ноября 2026

Плата — круглая Waveshare ESP32-S3-Touch-AMOLED-1.75 пользователя с PopkaWatch (проект `pomo-round`).

- Pi видит плату (`303a:1001`, `/dev/ttyACM0`). Сброс через порт (RTS при DTR=0, как esptool: `rst:0x15
  USB_UART_CHIP_RESET`) — плата **не переподключается** к USB, порт живёт сквозь сброс: проброс не рвётся при прошивке.
- Телефон: `/dev/ttyACM0` на `vhci_hcd.0/usb1/1-1`, `303a`, серийный — MAC-адрес платы, `root:dialout 0660`
  (`phablet` в `dialout`). `hello` (как спрашивает PopkaStudio, DTR=1, RTS=0) — ответ за 5 мс:
  `POPKA 1 board=amoled175 fw=2.5 project=pomo-round rev=26 …`.
- Сброс платы с телефона через проброс — дошёл (`rst:0x15` → `PopkaWatch start` → `setup done`), плата на телефоне
  осталась.
- Служба на Pi перезапущена — плата вернулась на телефон сама за ~3 с.
- Перезагрузка телефона (сделала соседняя сессия, 21 ноября): служба телефона загрузила драйверы на 14-й секунде,
  на 17-й — приставка доступна, плата взята, `/dev/ttyACM0` на месте — сама, без рук.
- Установка служб: корень телефона после неё снова только для чтения.

## Не проверено и открыто

- Кабель выдернуть рукой (keepalive), перезагрузка Pi.
- Две платы сразу; плата с мостом CH343 (P4, LCD-4B).
- Платы с мостами CP210x и CH340 — им нужны `usbserial` и свои драйверы, их не собирали.
- Плата прямо в телефон (без Pi): порт телефона умеет быть хозяином (`typec port0`: dual, data_role host/device),
  драйвер теперь есть — но переключится ли он, вставив плату, не проверяли.
- В первые миллисекунды после открытия порта (до «сырого» режима) терминал телефона возвращает плате её вывод (эхо) —
  плата видит мусорную команду. Так у любого Linux.

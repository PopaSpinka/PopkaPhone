# Планшет — экран стола

Рабочий стол телефона ([DESKTOP.md](DESKTOP.md)) — на планшете Android, приложением **НаомиФон**. Просьба пользователя
21 ноября 2026: «приложение на планшет — клиент, чтобы с нашего Пикселя картинку передавать, но управление также
остаётся с малинки, когда приложение запущено на планшете; и управление с планшета тоже — по тач-интерфейсу клики
работали и хваты».

**Сейчас (21 ноября 2026, метка `planshet-2026-11-21` — пользователь: «ок тогда зафиксируй результат»):** планшет
Galaxy Tab S5e показывает стол во весь экран вместе с монитором приставки; клавиатура, мышь и трекпад Pi управляют
как раньше, курсор Pi виден на планшете; касания — щелчок, двойной щелчок, хват окон, прокрутка и правый щелчок двумя
пальцами. В движении — 60 кадров/с без выброшенных, распаковка 15 мс, от кадра на телефоне до экрана планшета
76–85 мс. Монитор приставки — 60 Гц (выбор пользователя: так ровно и на планшете). Связь — TLS 1.3 по ключу. Плавность
глазами пользователь ещё не оценивал. Как развивать дальше — последний раздел.

**С того же дня планшет — свой экран в «Экранах»** ([SCREENS.md](SCREENS.md)), а не повтор монитора: стол на него
выводят отдельно (или вместе с монитором), он может быть главным — тогда стол его формы, 16:10, во весь экран. Стол на
него не выведен — на планшете заставка без дока; двойное касание заставки — «стол сюда». Киоск — раздел ниже.

```sh
tools/tablet install     # собрать (tablet/build.sh) и поставить на планшет по кабелю (adb)
tools/tablet pair        # сопрячь с приставкой — один раз (и после смены приставки или планшета)
tools/tablet run         # открыть; дальше — значок «НаомиФон» на планшете
tools/tablet log [сек]   # журнал приложения: кадры, распаковка, пинг до приставки
tools/tablet shot        # снимок экрана планшета → reports/tablet-shot.png
tools/tablet info        # модель, Android, экран, Wi-Fi
tools/tablet trace on    # каждый распакованный кадр — в журнал (с ближайшего открытия; off — выключить)
tools/tablet finger rtap 1100 986   # палец для проверок: dtap, rtap, scroll, drag («Как проверять»)
tools/tablet stop        # закрыть приложение
tools/tablet kiosk on    # киоск: на экране только «НаомиФон» (off — выйти, remove — совсем, status — как сейчас)
```

Планшет — на кабеле USB у Mac (режим разработчика, «Отладка по USB», ключ Mac разрешён «всегда»); работать с ним
кабель не нужен — только для установки, сопряжения и проверок.

## Как устроено

```
телефон ══ кабель USB (картинка напрямую, ввод — SSH) ══► приставка Pi ──► монитор (HDMI), как было
                                                            │  те же кадры HEVC, без нового сжатия
                                                            ▼
                                                   TLS 1.3, домашняя сеть (Pi — провод, планшет — Wi-Fi)
                                                            ▼
                                     планшет: MediaCodec (аппаратный HEVC) → SurfaceView, курсор Pi поверх
                                     касания → приставке → мышь стола (как от мыши Pi)
```

- **Картинку планшету отдаёт приставка, не телефон.** Телефон сжимает стол один раз — для приставки (HEVC, в такт её
  монитору, [PI.md](PI.md)); приставка пересылает планшету те же кадры. Второго зрителя у телефона нет (он у телефона
  один, [STREAM.md](STREAM.md)), нового сжатия нет, телефон о планшете не знает. Клавиатура, мышь и трекпад Pi
  управляют столом как раньше — и при открытом планшете тоже: монитор и планшет показывают одно и то же.
- **Курсор** рисует приставка (на мониторе — слоем KMS, [PI.md](PI.md), «Курсор»), в кадре его нет. Планшету
  приставка шлёт положение курсора (не чаще раза в 8 мс) и его картинку — тот же набор «Мягкая» под высоту кадра на
  экране планшета (`View`), форма — от стола (`Cursor`). Касание курсор на планшете прячет (палец — сам себе курсор),
  движение мыши или трекпада Pi — показывает.
- **Касания — мышь стола** (`tablet/…/Gestures.java`): приставка ставит курсор в точку касания и нажимает кнопку там
  же, а движение пальца идёт тем же досчётом, что движение мыши (`motion.h`): у каждого касания своя метка времени
  планшета, приставка переводит её в свои часы по наименьшей задержке за 4 с — разброс Wi-Fi не дёргает
  перетаскиваемое окно.

  | На планшете | На столе |
  |---|---|
  | коснуться и отпустить | щелчок; второй быстро и рядом встаёт ровно на место первого — двойной щелчок |
  | коснуться и повести | хват: кнопка нажата в точке касания — окна, выделение, ползунки; отпустил — отпущена |
  | два пальца повести | прокрутка за пальцами (как трекпадом приставки), после — по инерции |
  | двумя пальцами коснуться | правый щелчок |
  | перо над экраном | наведение |
  | касание, когда стол ушёл («без дока») | будит стол, как щелчок мыши |

  Кнопку палец нажимает не сразу, а через 90 мс неподвижности или как только сдвинется: второй палец за это время
  делает прокрутку или правый щелчок, а не хват первым пальцем.
- **Связь** (`pi/dock/tablet.*`, протокол — `tablet.h`): TLS 1.3 на порту 8490 приставки (OpenSSL Pi — системный,
  объявления в `ssl_min.h`, как у cairo). Сертификат приставки (EC P-256) планшет сверяет по отпечатку SHA-256 из
  сопряжения; первое слово планшета — ключ (32 случайных байта); не тот или нет за 3 с — закрыто. Планшет один:
  новый, сказавший ключ, сменяет прошлого. Рукопожатия — своими потоками (не держат идущий показ), отправка — своим
  потоком приставки, главный круг ничего не ждёт.
- **Очередь кадров** у приставки — не больше 6 кадров (3 МБ); ядру — не больше 128 КБ неотправленного
  (`TCP_NOTSENT_LOWAT`), иначе кадры копились бы в сокете. Wi-Fi не успевает — очередь прочь, дальше с опорного
  кадра: его приставка просит у телефона (не чаще раза в 0,5 с). Монитор приставки этого не замечает.
- **Приложение** (`tablet/`): Java без библиотек, собирается без Gradle и без скачиваний — `javac` → `d8` → `aapt2`
  → `zipalign` → `apksigner` из Android SDK на Mac (brew: `android-commandlinetools`, build-tools 35.0.0, платформа
  android-34; JDK 17). Ключ подписи — `private/tablet` (создаётся первой сборкой). Android 8+, во весь экран без
  панелей, экран не гаснет, Wi-Fi — в режиме малой задержки (`WIFI_MODE_FULL_LOW_LATENCY`), края экрана не отдают
  жест «назад» посреди перетаскивания. Кадр — в своих пропорциях, по краям чёрные поля. Связь — только пока приложение
  на экране.
- **Сопряжение** (`tools/tablet pair`): на Pi — сертификат (один раз) и новый ключ планшета в
  `/var/lib/naomi-dock/tablet` (только root); на планшет — адреса приставки (числом и `naomi-pi.local`), порт,
  отпечаток и ключ — в личную папку приложения (`run-as`: приложение собрано отлаживаемым). Ключ на Mac не ложится.
  Сопрягли снова — прежний ключ больше не годится.

- **Распаковка** (`VideoDecoder.java`): MediaCodec, аппаратный HEVC планшета, прямо на поверхность `SurfaceView`
  (кадр под экран планшета масштабирует сам композитор Android). Запускается с первого опорного кадра —
  VPS, SPS и PPS из него же; сбился — заново с опорного (`KeyFrame` приставке). Два найденных на Galaxy Tab S5e
  места (21 ноября 2026, декодер `OMX.qcom.video.decoder.hevc`):
  - **Кадр на экран — с меткой «сейчас»** (`releaseOutputBuffer(index, System.nanoTime())`). С `render = true`
    меткой была метка кадра — часы телефона: распакованные кадры стояли в очереди экрана по одному на обновление,
    декодеру не хватало буферов, и в движении задержка росла — распаковка 56 мс в среднем, к концу перетаскивания
    110–118. Теперь накопились — экран берёт свежий, прежние выбрасывает: 14–20 мс.
  - **Скорость декодера — числом** (`KEY_FRAME_RATE` 60, `KEY_OPERATING_RATE` 120): частоты драйвер ставит по
    частоте кадров, а из меток неровного потока (стол рисует только перемены) он её не выводит — «Unable to convey
    fps info to driver»; `Short.MAX_VALUE` драйвер Qualcomm отвергает. Плюс ключи Qualcomm — кадры в порядке
    распаковки и малая задержка (`vendor.qti-ext-dec-picture-order.enable`, `…-low-latency.enable`); `KEY_LOW_LATENCY`
    — с Android 11, у планшета 10.
- **Слушатель показа кадра — без блокировки декодера.** MediaCodec зовёт его, держа свою блокировку слушателей, а под
  ней же его поток шлёт и прочие события. Слушатель ждал блокировку декодера, пока поток связи под ней сидел в
  `queueInputBuffer` (тот ждёт поток MediaCodec) — взаимная блокировка: картинка на планшете застыла посреди
  открытия «Настроек» (21 ноября 2026, стеки потоков — `jdb` через `adb jdwp`). Теперь у замера свои карта и
  блокировка; 16 перетаскиваний окна подряд — без остановок.
- **Путь кадра — цифрами в журнале планшета** (`tools/tablet log`, раз в секунду): кадров, Мбит/с, распаковка и
  «от кадра на телефоне до экрана планшета» — приставка шлёт время кадра и в своих часах (часы телефона она сверяет
  сама), планшет переводит его в свои по пингу (`Pong` с часами приставки, лучший из 20), конец — метка показа кадра
  (`setOnFrameRenderedListener`). `tools/tablet trace on` — каждый кадр.
- **Палец для проверок** (`TestFinger.java`, `tools/tablet finger dtap|rtap|scroll|drag X Y …`): жест — событиями
  MotionEvent в тот же разбор касаний, шагом 8 мс, как у сенсора. Сенсор планшета adb писать не даёт (SELinux,
  `/dev/input/event2` — Permission denied), а `input tap` — один палец и ~0,5 с на касание (запуск Java): двойного
  касания (порог стола — 400 мс, как у Qt) и двух пальцев им не сделать. Принимает только отправителя с правом
  `DUMP` — оно есть у adb, у приложений на планшете его нет.
- **`tools/naomi` планшет не трогает:** телефон в ADB — только `device:redfin` (так он называет себя и под Ubuntu
  Touch), иначе с планшетом на кабеле `tools/naomi` шёл бы к нему («нужен SSH»).

## Экран стола: заставка и двойное касание (21 ноября 2026)

- **Свой экран.** Планшет, подключившись, называет приставке свой экран (`Screen`: 2560 × 1600 и какие обои заставки у
  него есть), приставка объявляет телефону экран `tablet` ([SCREENS.md](SCREENS.md)). Что на планшете, решает телефон:
  в `Show` приставке — показывает ли стол монитор, планшет или оба. Планшету стол не показывают — приставка говорит
  ему `Hello` с `desk: 0` и кадров не шлёт.
- **Заставка** (`SplashView.java`) — обои стола во весь экран и часы с датой: тот же вид и место, что у монитора
  приставки без дока (шрифты Google Sans Flex и Google Sans — в приложении, `assets/fonts`, кладёт `build.sh` из
  `downloads/fonts`; место и размер — из настроек стола «Без дока», сообщение `Splash`). Обои присылает приставка
  (`Wallpaper`, они у неё от телефона), они и настройки помнятся — заставка есть с первого кадра приложения и без
  связи. Стол пришёл — заставка тает с первым кадром на экране (метка показа кадра декодера; не отметился — через
  1,5 с): обои за 0,2 с, часы уходят вверх за 0,14; стол ушёл или приставки не видно — проявляется обратно.
- **Двойное касание заставки** (второе за 0,4 с и не дальше 80 dp) — `Wake` приставке, та — телефону: стол на планшет
  (включается, переезжает или планшет добавляется — как решит телефон, [SCREENS.md](SCREENS.md), «Пробуждение»).
  Одиночные касания заставки ничего не делают.
- **Главный планшет** — приставка называет телефону форму стола по экрану планшета: 1280 × 800 точек, кадр
  2400 × 1500; монитор приставки при этом на заставке (или показывает тот же кадр с полями, если стол выведен и на
  него). Клавиатура и мышь приставки управляют столом на планшете, их курсор на нём виден.

## Киоск (21 ноября 2026)

Просьба пользователя: «режим киоска: выключено всё, жесты, было только наше приложение; и чтобы я мог тушить экран
кнопкой полностью». Ответ на вопрос «как»: полный киоск — приложение владельцем устройства.

- **Владелец устройства** (`AdminReceiver`, `res/xml/device_admin.xml`): назначается одной командой adb — её
  запускает пользователь: `tools/tablet kiosk on` (внутри — `adb shell dpm set-device-owner
  com.popka.naomiphone.tablet/.AdminReceiver`; на планшете не должно быть учётных записей — 21 ноября их нет).
- **Что делает приложение-владелец** (`MainActivity.kiosk`, при каждом выходе на экран): закрепляет себя (lock task)
  без шторки, «домой», недавних и уведомлений; становится домашним экраном (после перезагрузки планшет открывается в
  него); выключает экран блокировки — кнопка питания гасит экран, вторым нажатием включает сразу в приложение
  (связь с приставкой рвётся на время сна и возвращается сама). Меню долгого нажатия кнопки питания (выключить,
  перезагрузить) оставлено.
- **Выйти:** `tools/tablet kiosk off` — киоск выключен, приложение остаётся владельцем (файл `files/kiosk-off`);
  `tools/tablet kiosk remove` — перестаёт быть владельцем (приказ принимается только от adb, как палец для
  проверок).
- **Включён и проверен** (пользователь запустил `tools/tablet kiosk on` 21 ноября 2026; проверки — клавишами и
  жестами через adb, состояние — `dumpsys`):

  | Что | Итог |
  |---|---|
  | владелец устройства, закрепление | `Device owner set`; `mLockTaskModeState=LOCKED`, на экране — `MainActivity` |
  | «домой», «недавние», «назад» | на экране остаётся «НаомиФон» |
  | жест от верхнего края (шторка) и от нижнего | шторки нет, приложение на месте; при столе на планшете жест идёт столу как касание |
  | кнопка питания: погасить, включить — трижды | экран гаснет, включается сразу в приложение (экрана блокировки нет), процесс тот же, закрепление держится; экран `tablet` на телефоне: «нет связи» → «заставка» через ~1 с после включения |
  | двойное касание заставки в киоске | стол пришёл на планшет (главный, 16:10) |

- **Падение при гашении экрана — исправлено.** Первая проверка кнопки питания: после включения на экране рабочий
  стол Samsung, закрепления нет. Причина — в журнале: `NetworkOnMainThreadException` в `Link.stop()` — приложение
  закрывало TLS-подключение потоком интерфейса (`onPause`), Android за запись в сеть из него роняет процесс; так оно
  падало при каждом уходе с экрана и раньше, просто этого не было видно. Теперь подключение закрывает свой поток.
- **Не проверено:** перезагрузка планшета (должен открыться сразу в приложение — оно домашний экран), меню долгого
  нажатия кнопки питания, настоящие палец и кнопка. `mWakefulness=Dozing` при погашенном экране — что при этом
  показывает сам экран (чёрный или часы Samsung), видно только глазами.

## Протокол

`pi/dock/tablet.h` (там же — описание каждого поля); приложение — те же номера в `Link.java`. Сообщение — как у
телефона ([STREAM.md](STREAM.md), «Протокол»): `u32` длина (тип + тело), `u8` тип, тело; little-endian; координаты —
доли кадра 0…1. Поверх TLS 1.3, порт 8490 приставки.

| Тип | Кто → кому | Тело |
|---|---|---|
| 1 Hello | приставка → планшет | JSON: `desk` (1 — стол идёт, 0 — нет), `width`, `height` (кадр), `codec`, `gen`; новый — декодер заново с опорного |
| 2 Video | приставка → планшет | `u64` захват (часы телефона — метка для декодера), `i64` он же в часах приставки (0 — не сверены), `u8` флаги (1 — опорный), HEVC Annex B |
| 3 Pong | приставка → планшет | `u64` время планшета из Ping, `i64` часы приставки — сверка часов |
| 4 Cursor | приставка → планшет | `u8` виден, `f32` x, `f32` y — курсор Pi |
| 5 CursorImage | приставка → планшет | `u16` n, `u16` hotX, `u16` hotY, `u32[n·n]` ARGB без умножения альфы |
| 6 Splash | приставка → планшет | JSON заставки: `clock`, `clockX`, `clockY` (1/10000 экрана), `width` (ширина стола, точки) |
| 7 Wallpaper | приставка → планшет | `u8[16]` хэш, JPEG обоев стола (пусто — градиент); когда хэш планшета не тот |
| 8 Light | приставка → планшет | `u8` авто (1 — яркость экрана планшет ведёт сам), `u8` уровень, 1…100 % — яркость со стола ([SCREENS.md](SCREENS.md), «Яркость планшета») |
| 10 Auth | планшет → приставка | `u8[32]` ключ, имя планшета — первое слово, за 3 с |
| 11 Ping | планшет → приставка | `u64` время планшета, раз в 0,5 с; тишина 3 с — закрыто |
| 12 Pointer | планшет → приставка | `u8` кнопки (1, 2), `f32` x, `f32` y, `u64` время касания (мкс, часы планшета) |
| 13 Scroll | планшет → приставка | `f32` x, `f32` y, `f32` dx, `f32` dy (ход пальцев), `u8` пальцы на экране, `u64` время |
| 14 KeyFrame | планшет → приставка | нужен опорный кадр |
| 15 View | планшет → приставка | `u16` ширина, `u16` высота картинки на экране планшета — размер курсора |
| 16 Wake | планшет → приставка | двойное касание заставки — «стол сюда» |

## Что не так или не проверено

- **Задержка вдвое больше, чем у монитора** (70–85 против 34–41 мс): распаковка у планшета 15 мс против 4 у Pi, и
  вывод на экран через композитор Android — ещё ~25 мс. Плюс у касания — путь до приставки и её досчёт (~10 мс).
- **Частота — монитора приставки:** стол рисует кадры в такт ему. При 75 Гц планшет (60 Гц) показывал 4 из 5;
  пользователь выбрал 60 Гц (21 ноября 2026) — ровно и на мониторе, и на планшете.
- **Заставка и двойное касание** — проверены пальцем для проверок (`tools/tablet finger dtap`), настоящим пальцем — нет.
- Без монитора у Pi приёмник не запускается (`naomi-dock` — хозяин дисплея) — планшет без монитора не работает.
- Звук — на мониторе приставки, планшету не идёт. Клавиатуры планшета нет — печатать клавиатурой Pi.
- Стол 16:9, экран планшета 16:10 — поля сверху и снизу, пока главный экран — монитор; главным планшет — без полей
  ([SCREENS.md](SCREENS.md)).
- Плавность глазами пользователь ещё не оценивал.

## Как проверять

- **Всё — на настоящем столе через приставку**, как у пользователя; он часто сам за столом — перед каждым касанием
  снимок (`tools/tablet shot`): та ли программа и то ли место. Экран планшета повёрнут на 270°, координаты
  касаний — пиксели снимка (2560 × 1600).
- **Касания:** один палец — `adb shell input tap X Y`, `input swipe X1 Y1 X2 Y2 МС` (хват); двойное касание, два
  пальца, ровный хват — палец для проверок `tools/tablet finger` (`TestFinger.java`).
- **Что на столе на самом деле** — `tools/naomi shot desk` (сцену рисует телефон заново): так отличить застывшую
  картинку планшета от настоящего состояния стола.
- **Цифры:** `tools/tablet log` — кадры, распаковка, путь до экрана, пинг; журнал приставки (`tools/pi log`) —
  «планшет: кадров N/с, Мбит/с» и подключения; покадрово — `tools/tablet trace on`.
- **Зависло приложение** — стеки потоков: `adb forward tcp:8711 jdwp:$(adb shell pidof com.popka.naomiphone.tablet)`,
  потом `jdb -attach localhost:8711`, `suspend`, `where all`, `resume` (JDK 17; `debuggerd` без root не даёт).
- Протокол без планшета — тем же клиентом на Python с Mac (TLS, Auth, Hello, кадры в файл → `ffmpeg`); так
  проверялась приставка до первого запуска на планшете.

## Как развивать дальше

Что просится следующим — по пользе; ни одно не начато.

- **Задержка (сейчас 76–85 мс, у монитора 34–41).** Из чего: сжатие на телефоне ~16 мс, кабель ~2,6, Wi-Fi до
  планшета несколько мс (кадр 40–85 КБ), распаковка 15, вывод через композитор Android ~25–30. Куда смотреть: показ
  кадра своим слоем `SurfaceControl` (API 29) с моментом показа — вместо очереди `SurfaceView`; меньший кадр для
  планшета (2400 × 1350 распаковывается дольше, чем 1920 × 1080) — но кадр общий с монитором, меняется только
  вместе с ним («Настройки» → «Резкость»).
- **Планшет главным экраном** — сделано (стол его формы, [SCREENS.md](SCREENS.md)); осталось: такт от обновлений
  экрана планшета (`Choreographer`), а не монитора; приставке — работать без монитора (сейчас `naomi-dock` без дисплея
  не запускается — нужен режим без KMS: такт по своему таймеру, курсор — только планшету).
- **Звук на планшете:** приставка уже получает звук стола (`Audio`, [PI.md](PI.md), «Звук на мониторе») — переслать
  его планшету тем же путём и играть `AudioTrack` с задержкой, равной задержке картинки; выбор, где звучит, —
  в окне звука стола.
- **Клавиатура планшета:** экранная клавиатура Android → `Key` с текстом (как клавиатура Pi: `input.onKey` в
  `main.cpp`); кнопка её показа на планшете.
- **Жесты:** щипок — масштаб (Ctrl + колесо), долгое касание — правый щелчок или «тащить»; жесты от краёв —
  «домой», шторка (сейчас края закрыты от жестов Android только на 40 dp).
- **Без приставки:** планшет — прямым зрителем телефона (у телефона зритель один, вход — только SSH: нужен второй
  зритель и свой вход для Android) — большая переделка, не нужна, пока есть Pi.
- **Сборка «по-настоящему»:** сейчас приложение отлаживаемое (ради `run-as` при сопряжении и `jdb`). Неотлаживаемое —
  сопряжение другим путём (код на экране стола или QR). Ключ подписи — `private/tablet`: потерять — обновить
  приложение поверх нельзя, только удалить, поставить и сопрячь заново. Новый сертификат приставки (папка
  `/var/lib/naomi-dock/tablet` стёрта, Pi перепрошит) — тоже сопрячь заново.

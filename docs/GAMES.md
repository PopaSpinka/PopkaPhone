# Игры

**Игры приставок на рабочем столе** ([DESKTOP.md](DESKTOP.md)). Просьба пользователя 21 ноября 2026: «добавим игры —
Денди (NES) и PS1, начнём с Денди… N → GAME — панель снизу, как у Android: значок, название… лучший эмулятор, нативно…
стрелки — крестовина, X и Z — A и B, Select и Start — C и V, R — перезагрузить приставку… игра в своём окне, без
элементов управления эмулятором, только полоса сверху: крестик и „в док“… кинул новую игру в папку — сама появилась в
списке». Сделаны **Денди (NES)** и, тем же днём, **PlayStation (PS1)** — первой Need for Speed: High Stakes.

- **Где игры:** папки `~/Games/NES` (`.nes`, `.unf`, `.unif`) и `~/Games/PS1` (образ диска: `.cue` с его `.bin`,
  `.chd`, `.pbp`, `.m3u`, `.iso`, `.img`; одинокий `.bin` — тоже) на телефоне; игра может лежать и в своей папке
  внутри (`PS1/Need for Speed - High Stakes/….cue`). Игра Windows — файл `.win` в `~/Games/Windows`: её запускалка
  ([WINDOWS.md](WINDOWS.md), «В списке игр»). Положил файл — игра в списке, убрал — её нет: оболочка следит за
  папками, перезапускать ничего не надо. Имя в списке — имя файла без расширения и пометок в скобках:
  `BattleCity (Japan).nes` → «BattleCity».
- **Меню N → GAME:** плитка открывает под меню модуль **«03 GAMES»** — как «03 ANDROID» (открыли один — другой
  закрылся): строка — грань слева (янтарь — игра идёт, вполсилы — запускается или свёрнута), значок-геймпад, имя,
  справа — система (`NES`, `PS1`). Щелчок — запустить; по идущей — показать её окно. Игр нет — подсказка, куда их класть.
- **Игра одна.** Выбрали другую — первая закрывается (память картриджа сохранит), вторая запускается следом.
- **Окно** — как у «Терминала» и браузера: полоса 40 (значок, имя, система), справа **«в док»** и **крестик**; углы
  «непрерывные», рамка .16; тянут за полосу, двойной щелчок — развернуть, края — размер (не меньше 320 × 280). Картинка
  — по высоте или ширине окна с пропорциями системы (у NES пиксель шире, чем выше, — 8 к 7; у PS1 экран 4 к 3),
  поля чёрные. Ни меню, ни
  настроек эмулятора в окне нет.
  - **«в док»** — полосы нет, игра во всю свободную область; «в окно» и крестик — на панели стола (как у окна Android
    «на весь экран»).
  - **крестик** — закрыть игру.
  - Пока игра открыта — её имя на панели за WEB (и TERM): щелчок — свернуть (игра встаёт **на паузу**, процессор — 0)
    или показать.
  - Место окна, «развёрнуто» и «в док» помнятся: `~/.config/naomi/desktop/game.conf`.
- **Кнопки** — по месту клавиши, раскладка не важна (в русской X — это «Ч»):

  | Клавиша | Денди (NES) | PlayStation |
  |---|---|---|
  | стрелки | крестовина | крестовина |
  | X | A | крест ✕ |
  | Z | B | квадрат □ |
  | S | — | треугольник △ |
  | A | — | круг ○ |
  | Q, W | — | L1, R1 |
  | E, D | — | L2, R2 |
  | C | Select | Select |
  | V | Start | Start |
  | R | Reset — кнопка «сброс» на самой приставке: игра начинается заново | то же |

  Кнопки PS1 выбраны пользователем из двух вариантов (21 ноября 2026).

- **Геймпад** (просьба 21 ноября 2026, вечер: «подключим его к нашему эмулятору Денди и PlayStation 1, чтобы он был по
  умолчанию… с дефолтной раскладкой для всех игр»). Геймпад, подключённый к телефону (Bluetooth или USB), работает в
  любой игре сразу, вместе с клавиатурой; включили его посреди игры — подхватывается сам. Кнопки — **по месту**, как у
  геймпада libretro (у геймпадов Xbox подписи другие, места те же):

  | Геймпад (место; подпись Nintendo и 8BitDo) | Денди (NES) | PlayStation (DualShock) |
  |---|---|---|
  | крестовина | крестовина | крестовина |
  | левый стик | крестовина (дальше половины хода) | левый стик |
  | правый стик | — | правый стик |
  | правая (A) | A | круг ○ |
  | нижняя (B) | B | крест ✕ |
  | верхняя (X) | турбо-A | треугольник △ |
  | левая (Y) | турбо-B | квадрат □ |
  | L, R / ZL, ZR | — | L1, R1 / L2, R2 |
  | нажать стик | — | L3, R3 |
  | − / + | Select / Start | Select / Start |
  | Home | — | **ANALOG** — стики вкл. / выкл., как кнопка на DualShock |

  Турбо — у самого Mesen (его X и Y), скорость — его по умолчанию. У PS1 геймпад — **DualShock**: с играми без стиков
  он цифровой, игры под DualShock ядро переводит в режим стиков само (NFS High Stakes — через ~1 с:
  `Pad1: Auto-enabling dualshock analog mode`); Home — то же, что L1 + R1 + Select (сочетание ANALOG у ядра), на
  клавиатуре — Q + W + C. Геймпадов несколько — все за первого игрока.

- **Геймпад и станция** (просьба 21 ноября 2026, вечер: «у геймпада есть док-станция, которая его врубает и вырубает,
  когда беру или ставлю… появился — ничего или из списка игр… беру геймпад — Денди сама стартует… выключается —
  ничего или закрыть текущую игру»). «Настройки» → **«Геймпад»** (`settings/GamepadPage.qml`): слева — геймпад сейчас
  (подключён — янтарём и его имя, нет — «не подключён»); справа — **«Когда геймпад появился»**: выпадающий список
  (вторая просьба того же вечера: «чтобы список игр выпадал, и опцию — запускать последнюю игру, в которую я играл»)
  — «Ничего», **«Последняя игра»** (справа — какая), черта, игры (имя, справа система, как в «03 GAMES»; новые игры в
  `~/Games` — сразу в списке; игр больше девяти — список крутится колесом; щелчок мимо — закрыть), и **«Когда геймпад
  пропал»**: «Ничего» или «Закрыть игру». По умолчанию — оба «Ничего». Делает стол (`Desktop.qml`, «геймпад и
  станция»), значения — `~/.config/naomi/desktop/gamepad.conf` (`appearGame` — путь игры или `last`, `goneClose`):
  - **появился** (геймпадов стало больше) — выбранная игра запускается («Последняя игра» — та, что запускали
    последней: из меню N или со станции, `last` в `game.conf`); идёт уже какая-то (та же или другая) — только
    показывается её окно: прохождение не теряется. Выбранную игру убрали из `~/Games` — ничего (на странице —
    подсказка янтарём);
  - **пропал** последний геймпад — через **3 с** идущая игра закрывается, как крестиком (сохранения пишутся). Вернулся
    раньше — игра идёт дальше: короткий обрыв Bluetooth игру не закроет;
  - геймпад, что уже был, когда стол создавали (перезапуск оболочки), — не «появился».

  Геймпады видит оболочка (`naomiGames.gamepads`, `game_library.cpp`, `scanPads`) тем же признаком, что `naomi-game`,
  по событиям каталога `/dev/input` (права узлу udev ставит следом — при отказе ещё раз через 0,5 с, до 6 раз); в
  журнале оболочки — `naomi.games: геймпад: …` и `геймпад отключён: …`, действия стола — `стол: геймпад появился —
  запускаю …`, `стол: геймпад пропал — закрываю игру …`.

- **Кнопки геймпада** (просьба 21 ноября 2026, ночь: «есть игры, где настройки на клаве… навести мышкой — шестерёнка…
  выбрать кнопку и назначить на клавишу… и в игре геймпад кликал бы на эти кнопки, желательно прямо с запущенной
  игрой»; вид выбран из макетов — меню «А», окно «01 Выноски»). В «03 GAMES» под мышью на месте подписи
  (WIN / NES / PS1) — **шестерёнка**; щелчок по ней — окно **«Кнопки геймпада»** этой игры (`game/PadKeysWindow.qml`;
  щелчок по строке — запуск, как раньше). Окно одно: открыто — показывается с другой игрой.
  - Сверху — игра (идёт — «ИДЁТ» бирюзой) и **«Как есть / Клавишами / Сбросить»**. Ниже — геймпад 8BitDo Ultimate
    (`game/PadArt.qml`, по фото и инструкции 8BitDo): стики, крестовина, A B X Y по месту (X сверху, A справа, B снизу,
    Y слева), − ★ Home +, сверху бамперы L1 R1 и курки L2 R2, лепестки P1 (правая рука) и P2 (левая) — пунктиром, они
    сзади. От кнопок — пунктир к плашке с клавишей, как в инструкции; середина — плашками со значками под корпусом.
    Плоская кнопка под ★ (профиль самого геймпада) телефону не видна — тусклая, не выбирается.
  - **«Клавишами»**: выбрал кнопку — щелчком по ней или по плашке, или **нажав её на самом геймпаде** (пока окно
    впереди, геймпад не играет, а выбирает) — снизу выезжает клавиатура (`game/PadKeyboard.qml`: латиница, цифры,
    знаки, Esc, Tab, Caps, Shift, Ctrl, Alt, пробел, стрелки; занятые клавиши — с меткой кнопки в углу). Щелчок по
    клавише или нажатие на настоящей клавиатуре — кнопка её жмёт; «Нет клавиши» — не жмёт ничего. Стики и
    крестовина — по направлениям (↑ ↓ ← → и «нажать»): назначил одно — выбрано следующее; у стиков — «Стрелки» и
    «WASD» разом. Одна кнопка — одна клавиша; две кнопки на одну клавишу — можно.
  - **«Как есть»**: геймпад читает сама игра (Денди и PS1 — `naomi-game`, раздел «Геймпад»), рисунок показывает, что
    делает каждая кнопка; нажатая на геймпаде — горит.
  - По умолчанию: игры Windows — «Клавишами» (пусто), Денди и PS1 — «Как есть».

  Хранит и переводит **оболочка** (`naomiPadKeys`, `shell/app/pad_keys.cpp`): раскладки — `~/.config/naomi/desktop/
  pads.json` (`{путь игры: {mode, keys: {кнопка: клавиша}}}`). Когда **впереди окно идущей игры** (`Desktop.qml`,
  `padTarget`) и у неё «Клавишами», оболочка забирает геймпады себе (`EVIOCGRAB`: ни `naomi-game`, ни Wine их больше не
  слышат — двойных нажатий нет) и шлёт клавиши окну игры клавиатурой Wayland, кодом по месту клавиши — как клавиатура
  зрителя (`StreamInput::keyToGame`). **Правка — сразу**, и в идущей игре: раскладка сменилась — зажатое отпущено,
  дальше по новой. Окно игры ушло назад (впереди другое, свёрнута, закрыта) — геймпад отпущен, зажатые клавиши
  отпущены, чтобы газ не залип. Стик: отклонён больше чем на половину — направление нажато, вернулся меньше чем на
  треть — отпущено (между — как было: не дребезжит); курки-оси геймпадов Xbox (`ABS_Z`, `ABS_RZ`) — так же. ★ у
  8BitDo в режиме Switch — кнопка «снимок» (`BTN_Z`). В журнале оболочки — `naomi.games: кнопки геймпада: клавишами
  (N) — <игра>`, `… выкл — геймпад у игры`, `… выбор кнопки в окне`, `… геймпад наш — <имя>`; кнопка с незнакомым
  кодом — `… незнакомая кнопка <код>` (по разу на код).

- **Сохранения:** память картриджа NES («батарейка», у игр, где она есть) и карта памяти PS1 (своя у каждой игры,
  128 КБ, в первом гнезде) — `~/.local/share/naomi/games/<система>/<игра>.srm`; пишется раз в 10 с, если сменилась,
  когда игру свернули и при закрытии.
- **Звук** — обычным потоком PulseAudio «Игры»: идёт туда же, куда весь звук стола (монитор приставки, наушники,
  телефон).

## Эмуляторы

Чужие программы как есть — ядра libretro из исходников закреплённой версии: архив с `codeload.github.com`, SHA-256
сверяется (`device/cores.sh`), сборка на телефоне под его процессор:

```sh
tools/naomi cores           # скачать (если ещё нет) и собрать → ~/naomi/cores/*_libretro.so
tools/naomi cores status
```

| Система | Ядро | Версия | Архив | Собранное |
|---|---|---|---|---|
| NES | Mesen 0.9.9, GPL-3.0 | [libretro/Mesen `0102910c`](https://github.com/libretro/Mesen/tree/0102910c39ad1a62bc3f784466f3f67ca9eae335) | 872 КБ | 3,1 МБ |
| PS1 | PCSX-ReARMed r26, GPL-2.0 | [libretro/pcsx_rearmed `7b0e8f8f`](https://github.com/libretro/pcsx_rearmed/tree/7b0e8f8fadfbce3d170d195b9d9eecaabfa08c8e) | 5,4 МБ | 1,8 МБ |

- **Mesen** — выбран как самый точный эмулятор NES, с режимом «Денди» и поддержкой пиратских картриджей (по его
  описанию; проверены Battle City — нами, Tetris — пользователем). Настройки — его собственные по умолчанию (регион — по игре:
  японская и американская — 60,1 кадра в с).
- **PCSX-ReARMed** — выбран пользователем из двух (второй — SwanStation): написан под ARM. У нас собрался с
  перекомпиляцией кода процессора PS1 в код ARM64 (`ari64`) и видеочипом на NEON (`gpu=neon`) — так он сам пишет при
  запуске. **BIOS PS1 не нужен:** без файла BIOS ядро берёт свою встроенную замену («HLE BIOS», предупреждает:
  возможны несовместимости). Настоящий BIOS, если появится, — положить в `~/.local/share/naomi/games/ps1/` (ядро ищет
  его там само; не проверено). Наши настройки ядра: первая карта памяти — через `naomi-game` (`.srm`), второй нет;
  остальное — по умолчанию.

## Как устроено

```
 стол оболочки (naomi-shell)                               naomi-game (своя программа, shell/apps/game)
   naomiGames (game_library.*): папки ~/Games → список       ядро эмулятора (dlopen ~/naomi/cores/*_libretro.so)
   NMenu «03 GAMES» → Desktop.activateGame                   кадр игры ×4 → буфер wl_shm → окно Wayland ─┐
   naomiApps.launch("game", масштаб, [система, ядро,         звук → PulseAudio («Игры»)                  │
                     файл, папка сохранений]) ───────────►   клавиши ← wl_keyboard (коды клавиш)         │
                                                             геймпады ← evdev (/dev/input), мимо стола   │
   GameWindow.qml: полоса, рамка, место картинки  ◄──────── окно (xdg_toplevel) от композитора ──────────┘
   stream_input.cpp: клавиши зрителя → коды клавиш окну игры (keyToGame)
```

- **`naomi-game`** — «приставка», своя, с нуля: один файл на C++, без Qt — libc, libwayland-client, libpulse; 21 МБ
  памяти с ядром. Запускает одну игру и показывает её окном Wayland оболочки, как браузер: оболочка узнаёт окно по pid
  и отдаёт столу. С ядром говорит по интерфейсу libretro (`third_party/libretro.h` — из тех же исходников Mesen, MIT).
- **Картинка** — кадр игры (NES 256 × 240), увеличенный программой в целое число раз без сглаживания (до высоты окна,
  не больше ×4 и 1,3 млн пикселей; PS1 меняет кадр на ходу — 256, 320, 512, 640 в ширину), в буфере `wl_shm`; до
  места в окне его дотягивает стол — пиксели остаются чёткими. Высоту картинки стол сообщает настройкой окна
  (`sendFullscreen`). Поверхность — `WebSurface`: края по контуру окна. Старший байт пикселя — всегда 255: стол
  читает его как прозрачность и у формата XRGB — с нулём кадр PS1 (ядро отдаёт RGB565, переводим сами) был чёрным, а
  ядро при этом работало (21 ноября 2026: искали «зависание» ядра, пока не сняли сырой кадр).
- **Темп — по расписанию и в такт стола.** Расписание — кадр ровно раз в период ядра (NES — 16,64 мс): по нему идёт
  звук. Стол рисует кадр, когда игра его положила, но не чаще 60 раз в с, и сообщает, что показал
  (`wl_surface.frame`); следующий кадр игры ждёт этого — но не дольше половины периода сверх расписания: не дождалась
  — кадр делается всё равно (стол покажет его вместе с прошлым). Три таких подряд (стол устойчиво медленнее игры: 60
  против 60,1 у NES) — расписание заново от этого мига и 5 с стола не ждём. Отстали больше трёх периодов (грузился
  диск) — тоже заново. Раньше кадр ждал стола до полутора периодов и после этого отсчитывал период заново — время
  терялось, очередь звука пустела, и звук заикался (пользователь о PS1, 21 ноября 2026: «заикается очень часто»).
- **Звук подстраивается под темп:** в очереди PulseAudio (100 мс) держится половина — мало — отсчётов делается чуть
  больше, много — чуть меньше (до ±0,5 %, линейный пересчёт), щелчков нет. Ждать места в очереди звука нельзя — кадры
  идут неровно (см. замеры). Играть PulseAudio начинает, когда в очереди половина (`prebuf`), и так же после каждого
  опустошения. С `prebuf` 0 он, оставшись без звука (игра PS1 грузит диск и стоит), уходил вперёд, и вся дальнейшая
  запись ложилась в уже сыгранное: поток есть, а тишина — так PS1 молчала (пользователь: «звука игры нет»); Денди без
  остановок играла. Очередь опустела — строка в журнале оболочки: `naomi-game: звук: очередь пустела N раз за 10 с`.
- **Поток игры — на больших ядрах** (два A76; выбираются по `cpu_capacity`).
- **Клавиши.** Зритель шлёт буквы текстом — стол переводит их в код клавиши (английская или русская буква на ней,
  без Shift и прочего) и отдаёт окну игры клавиатурой Wayland (`gameKeys` у поверхности, `StreamInput::keyToGame`).
- **Геймпады** `naomi-game` читает сам, мимо стола: устройства evdev в `/dev/input`, у которых есть кнопка
  `BTN_SOUTH` и крестовина или стик (у датчика отпечатка Pixel 5 «uinput-fpc» тоже есть `BTN_SOUTH` — для жестов, но
  нет ни крестовины, ни стиков: его не берём). Без захвата — браузер стола (Gamepad API) видит геймпад и дальше
  (захватывает его только оболочка — когда у игры впереди «Клавишами», раздел «Кнопки геймпада» выше).
  Подключили новое устройство — `inotify` на `/dev/input`: открыть его можно со второго события (права ставит udev);
  отключили — чтение кончается ошибкой, геймпад забыт; ядро потеряло события (`SYN_DROPPED`, игру морозили) — всё
  состояние заново (`EVIOCGKEY`, `EVIOCGABS`). Оси — к −32767…32767 по их пределам. Права — группа `android_input`
  (у стола она есть, игры её наследуют). Подключился или отключился — строка в журнале оболочки:
  `naomi-game: геймпад «Nintendo Switch Pro Controller» (/dev/input/event4)`. Сообщения ядра игроку (`ANALOG ON`) —
  туда же. Проверочный геймпад — `device/vgamepad.py` на телефоне (uinput, кнопки и стики как у Switch Pro).
- **Пауза** — сигналом: свернули — `SIGUSR1` (игра встаёт, пишет сохранение, звук молчит), показали — `SIGUSR2`
  (`naomiApps.pause`). Стол никто не смотрит — программу, как все программы стола, замораживает ядро
  ([DESKTOP.md](DESKTOP.md), «Выключатель»).
- **Разведка** (переменные окружения `naomi-game`, запуск руками — окно тогда встаёт на экран телефона):
  `NAOMI_GAME_LOG=1` — всё, что говорит ядро, и раз в ~10 с — сколько звука пришло от ядра и ушло в очередь; `NAOMI_GAME_VARS="ключ=значение,…"` — настройки ядра поверх наших;
  `NAOMI_GAME_DUMP=файл` — каждый 60-й кадр ядра как есть (ширина, высота, шаг строки, формат и строки кадра).
- **Меню N** (просьба в том же сообщении): плитки TORRENT и POPKATV убраны, **WEB** открывает браузер стола
  ([WEB.md](WEB.md)) — как WEB на панели; плиток пять, в один ряд: GAME, WEB, FILES, ANDROID, TERMINAL.

# Claude на столе

**Claude Desktop для Linux** — приложение Anthropic (чат, Cowork и вкладка Code — Claude Code) — на рабочем столе
НаомиФона ([DESKTOP.md](DESKTOP.md)), окном, как браузер и «Файлы». Просьба пользователя 21 ноября 2026: поставить
десктопную версию Claude Code, не терминальную, — «чтобы запускалась окном и работала на 100 %: не в контейнере, а
видела нашу систему от и до».

Чужая программа как есть: Anthropic, **бета для Linux** (с 30 июня 2026), Electron 45.3.3 (Chromium 156), пакет
`claude-desktop` 6.28899.2 для arm64. Требования Anthropic — Ubuntu 22.04+ или Debian 12+, x86_64 или arm64
([документация](https://code.claude.com/docs/en/desktop-linux)). У телефона Ubuntu 24.04 aarch64, glibc 2.39; все
библиотеки из зависимостей пакета уже есть, нет только `xdg-desktop-portal` и `xdg-open` (свой `xdg-open` — ниже,
«Ссылки»).

## Поставить и обновить

```
tools/naomi claude install    # новейший пакет arm64 (≈ 184 МБ, распакован 656 МБ) → ~/naomi/opt/claude-desktop
tools/naomi claude status     # что стоит и что новейшее в репозитории
```

`device/claude.sh` на телефоне. Корень системы только для чтения и полон (3,4 ГБ, свободно 0), поэтому не `apt`, а
распаковка пакета (`dpkg-deb -x`) в `/home`; пакет лежит в `~/Downloads/claude-desktop`. Проверка — как у apt:
отпечаток ключа `31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE` — из документации Anthropic, им проверяется подпись
`InRelease` (`gpgv`), по ней — SHA-256 списка пакетов, по списку — SHA-256 пакета. Тот же пакет второй раз не
качается; обновить запущенный Claude нельзя — сначала закрыть. Сам себя Claude на Linux не обновляет (так у Anthropic).

## Как устроено

- **Плитка CLAUDE** в меню N («02 APP», за TERMINAL — второй ряд; значок временный: звёздочка из восьми лучей). Окна
  нет — запустить; окно на виду и в фокусе — свернуть; иначе — показать. Пока окно есть — имя окна («Claude») на
  панели, там же, где окна программ Windows и приложения Android.
- **Запуск** — оболочка (`Desktop.qml`, `naomiApps.run("claude", …, freeze = false)`) запускает
  `~/naomi/opt/claude-desktop/naomi-claude` (`device/naomi-claude`), тот через `exec` — сам Electron: тот же pid. По
  pid стол и узнаёт окно: метку программы стола `NAOMI_DESK_APP` Chromium в `/proc/pid/environ` затирает именем
  процесса (проверено: метки там нет — окно без запуска оболочкой было «окном неизвестного процесса»).
- **Без заморозки.** Программы стола ядро замораживает, когда стол не смотрят ([DESKTOP.md](DESKTOP.md),
  «Выключатель»). Claude — нет: оболочка кладёт его не в подгруппу `desk`, а в свою `apps/claude-<номер>`
  (`AppLauncher::run`, `freeze`), а Electron и сам сразу уходит в свою группу systemd
  `app-com.anthropic.Claude-<pid>.scope` (проверено; его помощники, запущенные раньше, — zygote, видеочип, сеть,
  `crashpad` — остаются в `apps/claude-<номер>`). Его задачи идут и без монитора. «Закрыть принудительно» берёт обе
  группы ([DESKTOP.md](DESKTOP.md), «Закрыть принудительно»).
- **Окно** — то же, что у программ Windows (`game/GameWindow.qml`), система `app`: полоса 40 со значком и именем окна,
  «в док» и крестик, тянут за полосу, края — размер, двойной щелчок — развернуть. Размер окну задаёт стол — место под
  полосой в пикселях кадра; для Claude окно **всегда «развёрнуто»**, и не развёрнутое на столе (`alwaysMaximized`:
  размер развёрнутого окна по протоколу выбирает стол): так Chromium не рисует вокруг окна свою тень и не скругляет
  углы — это была треть его кадра (раздел «Скорость»). Углы скругляет стол, как у прочих окон; видна только
  объявленная Claude рамка окна (xdg window geometry). Сам Claude развернуться или вернуться не может — этим ведает
  стол. Место и «развёрнуто» — в `~/.config/naomi/desktop/claude.conf`. Крестик окна закрывает Claude совсем (выходит
  сам, код 0).
- **Масштаб 1** — Chromium рисует пиксель в пиксель с кадром стола. С `--force-device-scale-factor=1.5` он без
  протокола fractional-scale объявлял поверхность вдвое меньше буфера (буфер 1432 × 798, поверхность 716 × 399), и стол
  показывал не ту часть. Крупнее — масштабом в самом Claude (Ctrl + =), если нужно.
- **Клавиши** — клавишами Wayland, как окну Windows (раскладка композитора — английская), и с состоянием модификаторов
  (`wl_keyboard.modifiers`): без него Shift до Chromium не доходил — «Test» печаталось «test», «!» — «1». **Русские
  буквы** и всё, чего нет на английской клавиатуре («Ё», «№»), — текстом: `QInputMethodEvent` окну, Qt отдаёт его Claude
  по text-input-v3 (`TextInputManagerV3` в `Main.qml`; у Chromium — `--enable-wayland-ime
  --wayland-text-input-version=3`). **Особые клавиши и сочетания** (Enter, Tab, Esc, стрелки, Delete, F1–F12,
  Ctrl+…) — тоже клавишами Wayland напрямую: событие Qt без кода клавиши Qt Wayland отдаёт полю с включённым
  text-input-v3 текстом (`QWaylandSeat::sendFullKeyEvent`) — Backspace так доходил, а Enter терялся: ни отправки, ни
  новой строки. Всё это — `stream_input.cpp`, `keyToAndroid` и `linuxKey`, свойство окна `textCommit`.
- **Окна GTK** (выбор папки «Open folder…») — того же процесса, стол узнаёт их по pid и показывает отдельным окном
  (на панели — «SELECT FOLDER»).
- **Колесо** — Chromium превращает `wl_pointer.axis` в прокрутку только по событию `wl_pointer.frame`
  (`wayland_event_source.cc`: события колеса копятся до frame), а Qt объявляет `wl_seat` версии 4 — без frame — и
  сам его не шлёт: колесо до Claude доходило (журнал протокола: 187 событий axis на 16 щелчков), а чат не двигался.
  Стол дошлёт frame после каждого события колеса — только окну программы Linux (`WebSurface`, свойство
  `pointerFrames`; клиенту без frame в разборе событий указателя чужое событие опасно). Направление — как у браузера
  стола.

## Скорость (21 ноября 2026: «очень туго, ~20 кадров, задержки»)

Замеры на столе (Claude 6.28899.2, окно 1478 × 1068 пикселей кадра; загрузка — `/proc` раз в секунду, % одного
ядра; кадры — журнал протокола `WAYLAND_DEBUG=client` и счётчик кадров стола; щелчки — проверочной мышью приставки):

- **Рисует процессор.** Видеочип у Chromium на Wayland — это dmabuf с GBM, а драйвера `msm` для Mesa у телефона нет;
  процесс видеочипа поднимает Adreno через libhybris, но кадры столу — `wl_shm`, собранные процессором
  (`VizCompositorThread`). `--ignore-gpu-blocklist` — Chromium берёт Vulkan, тот не создаётся («`--ozone-platform=wayland`
  is not compatible with Vulkan») — опять процессор; `--in-process-gpu` (путь `wl_egl_window`, как у браузера стола) —
  Claude падает при запуске (SIGSEGV: libhybris в главном процессе Chromium). Видеочип для Claude — отдельная
  большая работа, не флаг.
- **Стол не тормозит:** от кадра Claude до разрешения рисовать следующий (`wl_callback.done`) — медиана 8–11 мс.
- **Невидимая анимация.** Как было, Claude перерисовывал окно целиком ~18 раз в секунду **в покое** (на снимках
  подряд меняется только курсор ввода; подсветка перерисовок Blink пуста — анимация слоя композитора): ~55 % ядра
  (страница 29 %, сборка кадра 18 %, главный процесс 9 %), и всякое переключение шло анимацией по ~20 кадров/с поверх.
  С `--force-prefers-reduced-motion` («меньше движения», запускалка `device/naomi-claude`) — в покое **3–5 %**, кадров
  нет; переключение сеанса — 1–3 кадра, первый через 70–120 мс, готово за 0,1–0,2 с.
- **Тень и углы Chromium — треть кадра.** Прокрутка чата колесом (по 20 щелчков вверх-вниз, мышь приставки) шла ровно
  40 мс на кадр (~25 кадров/с; из них Claude — 31 мс после `done`). Трасса Chromium (`--trace-startup`, формат json)
  на прокрутке: поток сборки кадра (`VizCompositorThread`, процесс видеочипа) занят 57 % времени, кадр
  (`Display::DrawAndSwap`) — 32 мс (медиана), и собирается он в три прохода: страница (51 плитка) — в отдельный буфер
  (14 мс), потом этот буфер и ещё слой — в окно (7,5 и 6 мс за штуку). Так Chromium рисует **свою тень и скруглённые
  углы** окна — только не развёрнутого; стол ни того ни другого не показывал (тень обрезана рамкой окна, углы
  скругляет сам). Развёрнутое окно 2400 × 1290 — в 1,7 раза больше пикселей — прокручивалось быстрее: 27 мс на кадр.
  Сделано: стол говорит Claude «развёрнуто» всегда (`GameWindow`, `alwaysMaximized`). То же окно 1478 × 1068
  (по два прогона): прокрутка **40 → 27 мс на кадр** (~37 кадров/с, p90 29–37 мс), сборка кадра 18 → 10–11 % ядра
  за прогон; щелчок по сеансу — первый кадр 90–105 → 59–66 мс (медиана), готово 146–180 → 131–137 мс; в покое — 1 %
  (было 3–5 %).
- **Не помогло** (замерено, не сделано): большие ядра — `schedtune.prefer_high_cap` группе `desk`, потом ещё подъём
  30 вместо 10: до правки прокрутка те же 40 мс (только первый кадр после щелчка 105 → 60 мс), после — 26,4 против
  26,5 мс; греть телефон не за что. `--enable-prefer-compositing-to-lcd-text` (прокрутка слоем) — те же 40 мс.
  «Прижато к краям» (`xdg_toplevel` tiled — нужна версия 2 `xdg_wm_base`, Qt объявляет 1; пробовали своим объектом
  через фильтр объявлений) — Electron оставляет тень: рамка окна с теми же полями 16 и 10.

Теперь кадр — два такта стола (26,7 мс при 75 Гц): Claude после `done` рисует ~15 мс, стол от кадра до `done` — ~11
(показывает кадр на своём такте). В один такт — только если Claude будет рисовать много быстрее: видеочип (свой GBM
поверх libhybris или Chromium с `wl_egl_window` — разбирать падение); это отдельная большая работа.

## Ссылки

Ссылки из Claude открываются **в браузере стола** новой вкладкой (21 ноября 2026, просьба пользователя). В Claude при
первом щелчке по ссылке — вопрос «Where should links open?»: выбрано «Open in default browser» (по умолчанию —
«Open in app», страница внутри Claude). Путь: Electron зовёт `xdg-open URL` → `xdg-open` стола
(`device/naomi-xdg-open`) → `org.naomi.Web.Open` на сессионной шине → стол (`Desktop.qml`, `openLink`): браузер на связи
— вкладка и окно наверх, нет — запускает его и открывает, как только тот на связи ([WEB.md](WEB.md), «Ссылки других
программ»). Не http(s) (файлы, `mailto:`) — код 3, «не умею».

**Почему `/usr/local/bin`.** Claude сужает свой `PATH` до системных папок, принадлежащих root и закрытых на запись
(`CLAUDE_DESKTOP_NARROWED_PATH`: `/usr/local/bin` и `/usr/local/sbin` — только если `/usr/local` и они сами такие,
затем `/usr/bin`, `/bin`, `/usr/sbin`, `/sbin`, `/snap/bin` и две папки NixOS в `/run/current-system`) — защита от
подмены программ. `xdg-open` из папки пользователя он не видит (проверено `strace`: искал `xdg-open` только там).
Поэтому `device/claude.sh` ставит `xdg-open` стола в `/usr/local/bin` (в образе она пуста) так же, как `naomi-usb` себя
в `/usr/local/sbin`: корень на запись на миг (`sudo`), файл root 755, корень снова только для чтения; тот же файл — не
трогает. Перепрошивка его сотрёт — `tools/naomi claude install` поставит снова. Это `xdg-open` всей системы: любая
программа, открывающая им http(s), откроет его в браузере стола. Обработчик GIO (`x-scheme-handler/https`) Claude не
спрашивает — проверено и убрано.

## Доступ к системе

Вкладка Code — не контейнер: Claude Code работает обычной программой от пользователя `phablet`, как Claude Code на Mac —
файлы, команды, службы. У `phablet` `sudo` без пароля на всё (проверено 21 ноября 2026), так что через `sudo` — и вся
система. Разрешение на команды и правки спрашивает само приложение. В виртуальной машине работает только Cowork — а он
на телефоне не пойдёт: нет `/dev/kvm`. Окно Claude — Chromium со своей песочницей страниц (`chrome-sandbox` без setuid —
песочница через пространства имён ядра), но это интерфейс, не руки Claude.

## Что не так или не проверено

- **Вход** — внутри окна: Google или почта с кодом; входит пользователь сам. Как пройдёт «Continue with Google», не
  проверено (ему нужен браузер).
- **Сессии с Mac** видны в списке слева (тот же аккаунт), их можно открыть окном. Печатать в такое окно — значит
  писать в ту сессию на Mac; при проверках в них ничего не вводить.
- **Перезапуск оболочки закрывает Claude** (он клиент её Wayland, как браузер) — с ним и задачи вкладки Code.
- **Меню Chromium** (правая кнопка, выпадающие списки) — всплывающие окна xdg_popup; стол их не показывает — не
  проверено, есть ли они у Claude.
- Нет у Linux-беты вообще: Computer Use, диктовка (документация Anthropic).
- Видеочип не работает — рисует процессор (раздел «Скорость»); нагрев при долгой работе не мерил.

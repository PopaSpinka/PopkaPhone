# НаомиФон — план

Черновик для обсуждения, 10 ноября 2026. Телефон — Google Pixel 5 (`redfin`), тестовый стенд.
Всё собираем с нуля в этой папке. Из старых папок берём только знания (что там нашли), а не код.

## Цель

Своя оболочка для телефона по логике НаомиОС, на базе готовой сборки Linux:

- свой интерфейс вместо Lomiri (штатной оболочки Ubuntu Touch);
- работает максимум железа Pixel: связь, Wi-Fi, Bluetooth, звук, камеры, GPS, NFC, все датчики;
- плавные 90 Гц, телефон не греется, долго живёт от батареи;
- режим разработчика: по кабелю видно всё (процессы, CPU, GPU, память, кадры, температура, ток батареи),
  можно гонять тесты и отлаживать;
- потом — связка с НаомиОС, как iPhone с Mac: общий буфер обмена, уведомления, файлы, Наоми.

## Почему база — Ubuntu Touch на Halium

Для Pixel 5 есть один живой порт Linux с почти всем железом: Ubuntu Touch 24.04 на Halium 13
(порт [dadrickpistachio/google-redfin](https://gitlab.com/dadrickpistachio/google-redfin), ядро 4.19).
По его таблице работают звонки, VoLTE, SMS, мобильный интернет, Wi-Fi, Bluetooth, NFC, камеры,
GPS, автояркость, поворот экрана, вибрация, фонарик, Waydroid. Не работают: отпечаток пальца,
двойное касание для пробуждения, вторая SIM.

Чистый Linux без Android-драйверов (mainline, postmarketOS) для этого процессора (SM7250) ещё не
принят в ядро; известные попытки — «пока непригодно» (камера, связь, датчики под вопросом).
Поэтому mainline — не сейчас.

Цена Halium: ядро 4.19 от производителя и драйверы Android 13 (сентябрь 2023), которые работают
в маленьком Android-контейнере через libhybris. Заводской Android на телефоне больше не обновляем.

## Как будет устроено

```
 загрузчик Pixel ─► boot / vendor_boot / dtbo (ядро 4.19 из порта)
   └─► systemd (Ubuntu 24.04, корень только для чтения)
        ├─ Android-контейнер: драйверы (дисплей HWC2, камера, звук, радио, датчики, GPS, BT, NFC)
        │      ▲ libhybris — мост между Android-драйверами и обычным Linux
        ├─ службы железа Ubuntu Touch: oFono (связь), BlueZ, NetworkManager, PulseAudio-droid,
        │  sensorfw (датчики), location (GPS), gst-droid (камера)
        ├─ naomid        — наша системная служба: одна точка ко всему железу и состоянию телефона
        ├─ naomi-shell   — наш композитор и оболочка: главный экран (блокировки нет), AOD, шторка,
        │                  переключатель программ, уведомления, клавиатура
        │      └─ программы — Wayland-клиенты (наши; Android-приложения — Waydroid, ANDROID.md)
        └─ naomi-devd    — режим разработчика (по кабелю)
```

### Чем рисуем интерфейс

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Qt 6 Quick + QtWayland Compositor прямо на HWC2** (так устроены Sailfish OS и AsteroidOS) | анимации на GPU, рисуем только когда что-то меняется, готовый Wayland-сервер для программ, мы сами владеем дисплеем → 90 Гц и vsync в наших руках; интерфейс правится без пересборки | нужен свой небольшой мост Qt ↔ HWC2 |
| wlroots + scenefx, как bcdesk в НаомиОС | общий код с НаомиОС | у wlroots нет рабочего бэкенда HWC2 для Halium — писать с нуля самое рискованное место |
| Mir 1, как сейчас у Lomiri | уже работает | Mir 1 уходит (в Ubuntu Touch 26.04 будет Mir 2); смены частоты в нём, по предварительным данным, нет |

**Предлагаю первый вариант.** С НаомиОС делим дизайн (палитра, шрифты, компоненты) и протоколы
связи, а не код композитора. Окончательно решаем после проверки 90 Гц (этап 4).

### 90 Гц — решено 10 ноября 2026

В C API libhybris смены режима нет, но Android-часть моста экспортирует внутренний
`HWC2::impl::Display::setActiveConfigWithConstraints` — вызываем его напрямую. По реальным меткам
вывода кадра (present-fence): 90,0 Гц, 2703 кадра подряд без пропусков. Подробности —
[DISPLAY.md](DISPLAY.md).

## Режим разработчика (naomi-dev)

Делаем **до** удаления Lomiri, чтобы, когда штатный интерфейс уйдёт, всё было видно.

- **Канал:** USB-кабель → ADB и USB-сеть → SSH по ключу. Wi-Fi-доступ включается отдельно.
  Наружу в сеть ничего не открыто.
- **На телефоне `naomi-devd`:**
  - живые метрики: каждое ядро CPU (частота, загрузка), GPU Adreno 620 (частота, занятость),
    память по процессам, все датчики температуры (корпус, CPU, GPU, батарея), ток и напряжение
    батареи → мгновенная мощность в мВт;
  - кадры от композитора: vsync, начало и конец отрисовки, реальный вывод на экран, пропуски, FPS,
    рывки; задержка «касание → кадр»;
  - скриншот и запись экрана, имитация касаний и жестов, запуск и остановка программ, горячая
    перезагрузка интерфейса без перезапуска;
  - журналы (systemd и Android logcat), дампы падений, трассировка (ftrace, perf);
  - HUD поверх экрана: FPS / CPU / GPU / °C — включается с Mac или жестом.
- **На Mac:** команда `tools/naomi` (для меня и для тебя) и панель в браузере: графики, зеркало
  экрана, журналы, запуск сценариев-тестов.
- **Страховка:** SSH и ADB не зависят от оболочки. Оболочка упала три раза подряд → безопасный
  режим. Заводской Android всегда можно вернуть — образ лежит на Mac.

## Холодный и плавный

- 90 Гц, когда касаешься экрана или идёт анимация; 60 Гц или меньше в покое (как в Android).
- Кадр рисуется, только когда что-то изменилось. Анимации — сдвиг, масштаб, прозрачность на GPU.
- Экран выключен → глубокий сон процессора (меряем ток), фоновые программы замораживаем. Пока отложено:
  телефон с погасшим экраном остаётся «живым» ([POWER.md](POWER.md), «Решение: сна пока нет»).
- Лишнее в Android-контейнере и в Ubuntu выключаем.
- Цели (уточним после замеров штатной системы): при свайпах 90 FPS, 95% кадров ≤ 11,1 мс;
  температура корпуса и ток в простое — не хуже, чем у Lomiri, а лучше.

## Открытые вопросы

- SIM-карта для проверки звонков, SMS и VoLTE: есть ли, какой оператор и страна.
- Android-программы через Waydroid — решено 18 ноября 2026: да, с Google Play, на рабочем столе, окно на приложение
  ([ANDROID.md](ANDROID.md)). Банки с Play Integrity, скорее всего, не пойдут; на экране телефона — ещё нет.
- Дизайн: как у НаомиОС (тёплый уголь, янтарь, моноширинный капс) или свой для телефона?
- Какие программы первыми: телефон, SMS, камера, галерея, браузер, настройки, музыка?
- Блокировка: экрана блокировки нет — решение пользователя (12 ноября 2026): включили экран — главный. Если
  когда-нибудь понадобится защита: отпечаток в порте не работает → PIN или графический ключ. Сам датчик отвечает: служба
  отпечатков Android работает, касание видно по прерыванию — им будит AOD ([SHELL.md](SHELL.md), «AOD»);
  распознавание отпечатка не проверяли.
- Данные на телефоне не шифруются (как в штатном Ubuntu Touch) — для стенда нормально.
- Экстренные вызовы на неофициальной системе не гарантируются — не основной телефон.
- Порт ведёт один человек (последнее изменение — сентябрь 2026); со временем, возможно, держим его сами.
- Место на Mac: свободно 39 ГБ, сборочной виртуальной машине нужно около 25 ГБ.
- Второй телефон — Nothing Phone 1 (едет, 21 ноября 2026): стол с приставкой и на нём. Разведка и план первых
  замеров — [NOTHING.md](NOTHING.md).

# Разработка

## Среда сборки на телефоне

Собираем прямо на Pixel 5: библиотеки — те же версии, что в системе, собранное запускается как есть,
место на Mac не тратится. Среда — копия корня Ubuntu Touch в `/userdata/naomi/devroot`, вход через
`chroot`; корень системы не меняется. Скрипт — `device/devroot.sh` (на телефоне — `/tmp/naomi-devroot.sh`):

```sh
sudo sh devroot.sh create      # копия корня, ≈ 1 мин, 3,3 ГБ
sudo sh devroot.sh packages    # apt update + пакеты сборки, ≈ 8 мин
sudo sh devroot.sh user "cd ~/naomi/… && cmake … && ninja"   # сборка от phablet
sudo sh devroot.sh root "apt-get install …"                    # пакеты в среду
```

В среду подключаются `/proc /sys /dev /run /android /home` (`--rbind`), поэтому исходники в
`/home/phablet/naomi` видны и в среде, и в системе, а программу из среды можно гонять с настоящими
драйверами. Службы при установке пакетов в среде не стартуют (`policy-rc.d` → 101).

Что стоит (10 ноября 2026, скачано ≈ 127 МБ): GCC 13.3, CMake 3.28, Ninja; Qt 6.10.2 из репозитория
UBports — Base, Declarative (Quick), Wayland (Compositor), ShaderTools с закрытыми заголовками, в том
числе `QtEglFSDeviceIntegration` (свой драйвер экрана для Qt); libhybris-dev (`hwc2_compatibility_layer.h`,
`hwcomposerwindow/hwcomposer.h`, pkg-config `libhwc2`, `hwcomposer-egl`, `libhardware`),
android-headers-30; EGL/GLES, Wayland, xkbcommon, libinput, udev, systemd, D-Bus. 18 ноября 2026 — ещё
libgstreamer1.0-dev (3,8 МБ с зависимостями): видео «Просмотра» стола (`shell/preview`); сам GStreamer 1.24 и
декодеры — в системе. 21 ноября 2026 — libpulse-dev (1,8 МБ): звук программы игр (`shell/apps/game`,
[GAMES.md](GAMES.md)); ядра эмуляторов собирает там же `tools/naomi cores`.

Расхождения среды с системой: в среде новее libhybris (сборка 2026-06-24, в системе — 2025-06-30),
заплатки glibc/systemd/glib/libinput. Мы используем C API libhybris — он совместим. Программам, которым
нужны библиотеки, которых нет в системе (например, `libQt6WaylandCompositor`), их надо поставить и в
систему — это решается вместе с установкой оболочки.

Проверено: программа на `hwc2_compat`, собранная в среде (`gcc … $(pkg-config --cflags --libs libhwc2
libhardware)`), запускается в системе и читает режим дисплея. Оболочка (`shell/`) собирается
`tools/naomi build` — [SHELL.md](SHELL.md). Скрипты для телефона `tools/naomi` кладёт в `~/naomi/bin`
(в `/tmp` они пропадают после перезагрузки).

## Кабель: ADB и сеть

Mac и телефон связаны USB-кабелем по двум каналам сразу, всегда, с первых секунд загрузки:

- **сеть** (CDC-NCM — её macOS понимает без драйверов): телефон — `10.77.0.1`, Mac получает адрес
  `10.77.0.100–254` от телефона (DHCP; `.2–.99` — постоянные: `.53` — DNS приставки). Шлюза и DNS телефон не выдаёт — интернет Mac через телефон
  не идёт. По ней ходит `tools/naomi` (SSH на `10.77.0.1`). Наоборот — бывает: на кабеле приставка Pi —
  интернет телефона идёт через неё ([PI.md](PI.md), «Интернет по кабелю»);
- **ADB** — запасной путь и `adb shell`.

Служба `naomi-usb` (`device/naomi-usb`) ставится один раз — `tools/naomi usb install`, состояние —
`tools/naomi usb`, вернуть как было — `tools/naomi usb uninstall`. Она заменяет `usb-moded` (его
выключает `mask`): тот ждал разблокировки от Lomiri, а когда не успевал поднять ADB — сам уходил в
«только зарядку», и кабель пропадал (так было, пока Lomiri нет).

Как устроено:

- Гаджет `g1` в `/sys/kernel/config/usb_gadget` (имя ждёт `adbd-functionfs.sh` Ubuntu Touch):
  функции `ncm.usb0` и `ffs.adb`, `18d1:4ee4`, «Pixel 5 NaomiPhone». Режим не переключается.
- ADB подключается к гаджету только после того, как `adbd` описал свои точки (`/dev/usb-ffs/adb/ep1`),
  а когда `adbd` закрывается, ядро отключает весь гаджет. Поэтому гаджет подключают хуки `adbd`
  (`/etc/systemd/system/adbd.service.d/90-naomi-usb.conf`): при старте — с ADB; при остановке — через
  3 с только сеть, если `adbd` так и не вернулся. `adbd` перезапускается сам (`Restart=always`).
- DHCP — отдельный `dnsmasq` службы `naomi-usb`: только на `usb*`, DNS выключен, аренды в памяти; каждая аренда —
  `naomi-usb add|old|del` (`--dhcp-script`): аренда `naomi-pi` — интернет через приставку.
- MAC-адрес Mac-стороны ядро (Android 4.19) выдумывает при каждом подключении гаджета, а задать его
  заранее не даёт (файлы `dev_addr`/`host_addr` до подключения отвечают «No such device»). Поэтому
  адрес Mac бывает разным; macOS при этом держит один интерфейс («Pixel 5 NaomiPhone», у нас — `en11`).
- При первом подключении macOS спрашивает, разрешить ли новый аксессуар, — разрешает пользователь.
- ADB пускает без ключа — так настроен порт (`ADBD_SECURE=0` в `/etc/default/adbd`), — и теперь
  открыт и при заблокированном экране (`usb-moded` включал его только после разблокировки). Кто
  подключит кабель, получит оболочку `phablet`, а с `sudo` без пароля — root. Для стенда так и задумано;
  закрыть можно ключом ADB Mac — это настройка безопасности, её делает пользователь.

Проверено 10 ноября 2026:

- после перезагрузки гаджет с ADB и сетью — на 14,9 с от старта ядра, Mac получил адрес на 19,4 с,
  оболочка — на 19,9 с; нового вопроса macOS не было;
- перезапуск `adbd`: на телефоне гаджет снова с ADB через 0,25 с; на Mac ADB — сразу, сеть — через
  2–3 с (новый адрес по DHCP). Открытые SSH-сессии по кабелю при этом рвутся — `tools/naomi` замечает
  обрыв за ≈ 6 с (`ServerAliveInterval`);
- Wi-Fi телефона выключен — всё работает по кабелю;
- скорость SSH (64 МиБ с телефона, с учётом входа): кабельная сеть ≈ 36 МБ/с, ADB ≈ 33 МБ/с,
  Wi-Fi ≈ 10 МБ/с; пустая команда — 0,22 / 0,24 / 0,43 с.

- `tools/naomi usb uninstall` возвращает `usb-moded` (режим `mtp_adb`, ADB на месте), `install` — снова
  наш кабель; оба — по кабелю или Wi-Fi, связь возвращается сама.

Не проверено: выдернуть и вставить кабель руками.
